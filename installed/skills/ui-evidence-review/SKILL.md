# UI 증거 검토

UI를 만들거나 고칠 때 실제 제품 근거와 화면 확인을 먼저 둡니다.

1. 기존 화면, 디자인 시스템, 사용자의 실제 목표와 작업 순서를 먼저 읽습니다. 근거가 없으면 새 시각 언어를 발명하지 않습니다.
2. 화면을 카드·그라데이션·가짜 데이터·AI 배지로 채우지 않습니다. 우주·로봇·관제 화면·채팅창·추상 아이콘은 제품 도메인이 요구할 때만 씁니다.
3. 카피는 대상, 상태, 다음 행동을 직접 말합니다. 미래 약속·기능 없는 헤드라인·빈 칭찬·긴 서술은 제거합니다.
4. 레이아웃, 서체, 색상, 여백, 모서리, 그림자, 애니메이션은 기능·위계·기존 시스템·접근성 중 하나로 이유를 설명할 수 있을 때만 적용합니다.
5. 모바일과 넓은 화면의 읽기 순서, 키보드 포커스, 색상 외 상태 표시, 가려진 조작, 불필요한 움직임을 확인합니다.
6. 가능하면 실제 화면을 렌더링하거나 조작해 확인합니다. 확인하지 못했으면 시각 품질을 통과로 표현하지 않습니다.

결과에는 바꾼 UI 요소, 실제 확인한 화면 상태, 확인하지 못한 시각 검증만 짧게 남깁니다.
