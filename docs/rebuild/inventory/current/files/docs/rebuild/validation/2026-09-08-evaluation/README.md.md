## 실제로 잘못 통과한 경로

채점 중 후보가 자신의 소스를 잘못된 구현으로 바꾸지만 메모리의 정상 함수로 결과를 반환하면 이전 채점기는 통과시켰습니다. 채점 전후 후보 파일을 비교하도록 바꾼 뒤 해당 회귀가 실패 처리됐습니다.

정상 구현의 `.pyc`를 만든 뒤 소스를 같은 크기·수정 시각의 잘못된 구현으로 바꿔도 이전 채점기는 통과시켰습니다. 격리 모드는 `PYTHON*` 환경 변수를 무시하므로 환경 변수만으로 바이트코드 쓰기를 제어하는 것도 충분하지 않았습니다. 명시적인 `-B`·UTF-8 인자와 매 검사마다 빈 캐시 경로를 사용한 뒤 현재 소스의 실패를 확인했습니다. [공식 실행 옵션](https://docs.python.org/3/using/cmdline.html).

준비된 요청이 바뀌면 같은 시험으로 채점하지 않습니다. 준비·채점 환경과 적용한 시간 제한을 기록하며 CPU·메모리 자원 제한 미적용을 표시합니다. 이는 [평가 환경이 결과에 미치는 영향](https://www.anthropic.com/engineering/infrastructure-noise)을 반영한 기록이며 자원을 통제한 경쟁 실험은 아닙니다.
