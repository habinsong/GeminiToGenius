# 작업 조회와 새 세션 연결 검증

전체 로컬 검사 141개가 49.572초에 통과했습니다. [실행 로그](tests.log)와 [검증 당시 소스 해시](verification.json)를 보존했습니다. 추가 모델 요청은 0회입니다.

## 재현과 구현

기존 `start`를 다른 세션 ID로 다시 실행하면 작업이 두 개가 되고 새 작업에는 이전 메모가 없었습니다. 이는 새 작업 생성 동작이며 기존 목표를 이어받는 명령을 대신할 수 없었습니다. 신규 조회·연결 검사 6개는 구현 전 모두 실패했습니다.

- `tasks`는 현재 작업공간의 저장된 목표·메모·검사 개수·연결을 읽기 전용으로 찾습니다. 상태 DB가 없으면 새로 만들지 않습니다. 긴 내용과 연결 목록은 일부만 반환하고 생략 여부를 명시합니다.
- 목록의 과거 성공은 현재 파일 검증으로 표시하지 않습니다. `status`는 전체 원래 명세와 현재 검증 상태를 반환합니다.
- `attach`는 작업 ID·목표·검증 결과·메모를 유지한 채 현재 세션에 연결합니다. 연결 변경은 트랜잭션으로 처리하며 중복 요청은 예산을 다시 채우지 않습니다.
- 같은 작업의 동시 연결 요청 두 개 중 하나만 활성 연결을 얻었습니다. 진행 중인 검사, 다른 현재 목표, 잘못된 작업공간·상태 경로, 손상된 명세는 거부했습니다.

## 설치된 진입점 확인

[설치된 패키지 시나리오](installed-scenario.json)는 매 단계에서 별도 CLI 프로세스를 실행했습니다.

| 순서 | 확인한 결과 |
| --- | --- |
| 기존 세션의 부분 검증·메모·중단 | 첫 검사 통과와 다음 행동을 저장했습니다. |
| 작업 후보 조회 | 같은 작업 ID와 저장된 메모를 찾았습니다. |
| 다른 세션에 연결 | 원래 목표·첫 성공·메모가 유지됐습니다. |
| 새 세션의 이벤트 재생 | 같은 목표와 다음 행동이 컨텍스트에 나타났습니다. |
| 남은 검사 실행 | 같은 작업에서 전체 검증이 통과했습니다. |

실제 Gemini나 Antigravity 모델을 실행한 시험은 아닙니다. 스킬의 작업 선택 능력이나 다른 세션의 실제 호스트 동작까지 증명하지 않습니다.

## 경계와 남은 한계

이전 실호스트 상태의 사본에서도 마이그레이션을 검사했습니다. 오래된 `last_stop`만으로 현재 유휴 상태를 추정하지 않고 `turn_open`을 정보 없음으로 두었습니다. [기존 상태 보존 검사](legacy-state-check.json).

`turn_open`은 마지막 훅 관측이며 PID나 파일 잠금이 아닙니다. 다른 활성 연결의 종료가 확인되지 않으면 기본 연결은 거부합니다. 실제로 이전 호스트가 종료됐다는 확인을 제공하는 `--previous-host-stopped`도 실행 중인 등록 검사를 우회하지 못합니다. 이 기능은 이전 호스트를 종료시키거나 이미 실행 중인 외부 파일 편집을 막지 않습니다.

호스트의 세션·체크포인트 복원과 GTG의 목표 연결을 구분했습니다. 현재 파일을 유지하고 저장된 상태를 다시 확인하는 경로입니다. [Gemini CLI 세션 관리](https://geminicli.com/docs/cli/session-management/), [파일 복원을 포함하는 체크포인트](https://geminicli.com/docs/cli/checkpointing/).
