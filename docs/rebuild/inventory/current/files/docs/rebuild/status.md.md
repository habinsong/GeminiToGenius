- 같은 사례·요청·채점기로 **실제 경쟁 비교를 처음 실행했습니다.** GTG(Gemini 3.8 Flash High)와 Claude Code가 각각 1/1 통과로 동률입니다. 우열은 주장하지 않습니다. GTG 팔은 테스트를 실제로 실행했고 Claude Code 팔은 권한 거부로 실행하지 못했다고 보고했으나, 현재 채점기는 산출물만 봅니다.
- Codex CLI는 사용자 설정 충돌과 로컬 프록시 부재로 실행되지 않았습니다. `compare`가 이를 `ungraded`로 표시하고 비교를 막았습니다. 패배로 세지 않습니다. OmO는 런타임 파일이 없어 실행되지 않았습니다. [실행 기록과 한계](validation/2026-09-09-real-comparison/README.md).
- 잔여 한도는 시험 전 주간 100%·5시간 100%, 두 요청 뒤 99%·98%였습니다. 전체 검사는 205개가 통과했습니다.

### 실행하지 않은 검증 대상 기록과 지시문 보안 검사

사용자께서 이번 구간에는 Antigravity·Gemini를 사용하지 말고 웹 조사와 로컬 검증으로 진행하도록 지시하셨습니다. 실제 모델 요청은 0회입니다.

- 공개 연구의 증거 묶음 개념(수행한 검사·검증하지 않은 영역·남은 위험)을 반영해 `gtg/coverage.py`를 추가했습니다. 검사 실행 중 실제로 실행된 Python 파일을 관찰합니다.
- `sitecustomize`를 임시로 주입해 `sys.monitoring`의 `PY_START`만 관찰하고 본 위치는 바로 끕니다. 하위 Python 프로세스도 포함되며 기존 `sitecustomize`를 가리지 않는 것을 시험으로 고정했습니다.
- `status`의 검사마다 `unexecuted_watch`, 증명서에 `unverified_scope`가 들어갑니다. 통과했지만 어떤 검사도 실행하지 않은 대상을 사실로 밝힙니다. Python 실행을 관찰하지 못하면 미실행을 주장하지 않습니다.
- 처음 구현의 미사용 `find_spec` 호출이 프로세스당 22~25밀리초를 쓰는 것을 실측으로 발견하고 제거했습니다. 이후 고정 비용은 약 4밀리초 이하이며 전체 검사 시간도 55초에서 31초로 돌아왔습니다.
- 스킬 공급망 연구를 반영해 배포 지시문의 제어·양방향·폭 없는 문자를 거부합니다. 폭 없는 공백·양방향 재정의·BOM으로 각각 확인했습니다.
- 신규 15개를 포함한 전체 216개 검사가 통과했습니다. [증거·측정·한계](validation/2026-09-09-evidence-coverage/README.md). 연구 원장은 81개 출처입니다.
- Antigravity의 새 `disable-slash-command` 플래그는 GTG 설계와 맞지만 실호스트로 확인하지 못해 적용하지 않았습니다. 다음 확인 후보로 원장에 남겼습니다.

### 비교 실행의 표준화

- 준비된 요청을 각 하네스에 그대로 전달하는 `evals/execution.py`와 `run` 명령을 추가했습니다. `{prompt}` 자리 표시가 없으면 거부하므로 팔마다 다른 문자열이 들어갈 수 없습니다.
- 시행마다 실행 시간·종료 상태·출력 크기를 기록합니다. 준비 단계부터 있었지만 항상 비어 있던 `runtime_observation`을 실제로 채웁니다. 한 시행은 한 번만 실행하며 시간 초과는 상태로 남기고 하위 프로세스를 정리합니다.
- 비교 보고서가 팔별 총 실행 시간과 관측하지 않은 시행 수를 함께 보고합니다. 관측이 없는 시행을 0초로 세지 않습니다.
- 참조 하네스 두 개로 준비→실행→채점→비교 전체를 실행했습니다. 요구를 모두 만족한 쪽만 1/1로 통과했고 시간도 각각 기록됐습니다. [파이프라인 결과](validation/2026-09-09-evidence-coverage/pipeline-comparison.json).
- 서브커맨드 이름과 충돌해 `run`이 `grade`로 잘못 분기하던 문제를 실제 CLI 실행에서 발견하고 고쳤습니다.
- 신규 8개를 포함한 전체 224개 검사가 통과했습니다. 토큰 사용량과 비용은 여전히 수집하지 못합니다.

### 실행 관찰의 경계 조건 하드닝

- 검증 범위가 2,000개 파일을 넘으면 목록 작성을 멈추고 미실행 목록을 `null`로 둡니다. 다 세지 못한 범위를 미실행으로 보고하지 않습니다.
- 신규 3개를 포함한 전체 227개 검사가 통과했습니다.
