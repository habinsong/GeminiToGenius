# 재개발 계획

최종 목표는 요청 하나로 관련 자료와 저장소를 조사하고, 작업을 끝까지 수행하며, 실패를 복구하고, 결과를 실제 증거로 설명하는 것입니다. 경쟁 도구보다 좋다는 판단은 같은 작업·모델·예산·채점 조건의 비교 결과로만 내립니다.

슬래시 명령·정교한 프롬프트·수동 스킬 선택을 필수로 만들지 않습니다. 불완전한 요청은 현재 저장소·오류·화면·직전 대화로 구체화합니다. 목적이나 데이터 안전이 달라지는 모호성만 질문하며, 독립적인 조사와 준비는 먼저 진행합니다. 작업 스펙·완료 조건은 에이전트가 작성하고 사용자는 자연어로 요청합니다.

## 우선 폐기할 설계

- 훅 개수나 문서의 단어 존재만으로 기능이 작동한다고 판정하는 검증입니다.
- 일반 작업까지 모든 파일 읽기·장문 계획서·무조건 다중 페이지·고정 500줄을 요구하는 규칙입니다.
- 설치를 먼저 바꾸고 마지막에야 확인하는 순서와 서로 다른 배포 사본입니다.
- 검증 없이 스킬과 훅을 늘리거나 매 호출에서 LLM 심사자를 추가하는 비용 구조입니다.

UI 결과의 맥락·위계·접근성·실제 동선 검증은 유지하되 디자인 선택을 문구 정규식으로 대체하지 않습니다.

## 작업 단위

각 단계는 실패 재현 → 구현 → 직접 검증 → 문서와 전체 목록 갱신으로 마무리합니다. 기존 동작을 삭제하는 단계에서는 대체 경로와 회귀 증거가 먼저 준비되어야 합니다. 구현 상태는 [진행 기록](../status.md)에 구체적인 파일·명령·결과로 기록합니다.

공개 문서 조사는 계속 갱신합니다. 자료의 최신성은 검색 순위가 아니라 공식 페이지·원본 소스·확인 날짜로 판단합니다. 실모델 검증은 로컬 계약으로 확인할 수 없는 항목에만 사용하고, 자동 반복·모델 대량 비교는 실행하지 않습니다.
