# 실행하지 않은 검증 대상을 사실로 기록

확인일: 2026-09-09. 실제 모델 요청은 0회입니다. 사용자께서 이번 구간에는 Antigravity·Gemini를 쓰지 말라고 지시하셨습니다.

## 왜 필요한가

공개 연구는 실행 피드백이 붙은 오라클만큼만 신뢰할 수 있다고 지적합니다. 통과한 테스트가 명세 전체를 뜻하지 않으므로, 검증 산출물마다 **무엇을 검증하고 무엇을 검증하지 못하는지** 밝히고 수행한 검사·검증하지 않은 영역·남은 위험을 담은 증거 묶음을 만들라고 제안합니다. 다른 연구는 각 상태에서 어떤 검증기가 적용되지 않았는지 기록해 미검증 범위를 측정 가능한 값으로 바꿉니다.

GTG는 지금까지 "검사가 통과했다"만 증명했고, 그 검사가 무엇을 건드리지 않았는지는 모델의 산문 설명에 맡겼습니다.

## 구현

`gtg/coverage.py`가 검사 실행 중 실제로 실행된 Python 파일을 관찰합니다.

- 임시 폴더의 `sitecustomize.py`를 `PYTHONPATH` 앞에 두어 인터프리터 시작 시점에 등록합니다. 검사가 만든 하위 Python 프로세스도 같은 방식으로 관찰됩니다.
- 관찰은 `sys.monitoring`의 `PY_START`만 사용하고 콜백에서 `DISABLE`을 돌려줍니다. 이미 본 코드 위치는 계측을 끕니다. `sys.monitoring`이 없으면 `sys.settrace`로 물러섭니다.
- 비어 있는 도구 ID를 찾아 쓰고, 어떤 단계든 실패하면 조용히 관찰을 포기합니다. 검사 자체를 방해하지 않습니다.
- 기존 `sitecustomize`를 가리지 않습니다. 남은 경로에서 원본을 찾아 이어서 실행하며 이 동작을 시험으로 고정했습니다.

`runner.execute`는 결과에 `coverage_observed`, `executed_watch`, `unexecuted_watch`를 넣습니다. `status`는 통과한 검사에만 `unexecuted_watch`를 전달하고, 증명서에는 **어떤 검사도 실행하지 않은 검증 대상**이 `unverified_scope`로 들어갑니다. `replay` 결과에도 같은 목록을 싣습니다.

## 실제 실행 확인

설치된 실행기로 만든 작업에서 통과한 검사가 무엇을 실행하지 않았는지 그대로 나왔습니다.

```
verified: True
  check unit passed | 실행 안 한 대상: ['untested.py']
unverified_scope: ['untested.py']
```

[증명서 원문](certificate-with-unverified-scope.json). 통과와 미검증 범위가 한 문서에 함께 있습니다.

## 성능 측정

관찰기는 검사 실행에 붙으므로 비용을 실제로 쟀습니다. 같은 명령을 7회 실행한 최소값입니다.

| 작업 | 관찰 없음 | 관찰 있음 | 차이 |
| --- | --- | --- | --- |
| 짧은 시작만 | 25.5ms | 29.3ms | +3.8ms |
| import 많은 실행 | 97.1ms | 94.7ms | -2.4ms |
| 계산 많은 실행 | 52.0ms | 53.3ms | +1.3ms |

처음 구현에는 결과를 쓰지 않는 `importlib.util.find_spec` 호출이 남아 있었고 이때는 프로세스마다 +22~25밀리초였습니다. 해당 줄을 지운 뒤 위 값이 됐습니다. 전체 검사 시간도 55초에서 31초로 돌아왔습니다. 비용은 작업량에 비례하지 않는 프로세스당 고정 비용이며, 측정 편차 범위 안에서 음수도 나옵니다.

## 함께 넣은 보안 검사

공개 스킬의 13.4%가 치명적 문제를 가졌고 SKILL.md에 보이지 않는 유니코드로 지시를 숨기는 공격이 보고됐습니다. 배포하는 모든 Markdown 지시문에서 제어·양방향·폭 없는 문자를 거부합니다. 폭 없는 공백·양방향 재정의·BOM을 각각 넣어 거부를 확인했고, 현재 원문에는 해당 문자가 없음을 검사로 고정했습니다.

## 경계 조건

- 격리 실행(`-I`, `-E`, `-S`)은 `PYTHONPATH`나 `site`를 쓰지 않으므로 관찰되지 않습니다. 오류로 만들지 않고 관찰 없음으로 처리해 미실행을 주장하지 않습니다.
- 검증 범위가 2,000개 파일을 넘으면 목록 작성을 멈추고 `unexecuted_watch`를 `null`로 둡니다. 다 세지 못한 범위를 미실행이라고 말하지 않습니다.

## 한계

파일 단위 실행 관찰입니다. 실행했다는 사실이 그 파일의 모든 동작을 확인했다는 뜻이 아니고 줄·분기 커버리지도 아닙니다. Python 실행을 관찰하지 못한 검사(셸·빌드 명령 등)는 `null`을 돌려주며 미실행을 주장하지 않습니다. `os._exit`나 강제 종료로 끝난 프로세스는 기록을 남기지 못합니다.

이 기능이 실제 모델의 보고 품질을 높이는지는 미검증입니다. 다음 실호스트 확인의 대상입니다.

## 재현되지 않은 실패 1건

이 구간 도중 전체 검사 한 번이 오류 1건으로 실패했으나 로그를 남기지 못했습니다. 이후 같은 명령을 4회 실행해 모두 통과했고 원인을 확정하지 못했습니다. 재현되지 않았다는 사실만 기록합니다.

[로그와 소스 해시](verification.json): 전체 216개 검사가 통과했습니다.
