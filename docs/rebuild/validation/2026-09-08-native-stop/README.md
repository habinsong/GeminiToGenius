# 실제 종료 후 재개 시험

**이 문서의 실제 호스트 시험은 실패했습니다.** Antigravity 2.12.2에서 작업 등록 뒤 첫 응답은 끝났지만 자동 재개와 등록 검증 실행이 일어나지 않았습니다. 당시 코드 보완은 로컬 계약 재생까지만 확인했으며 이 실패 기록을 성공 기록으로 바꾸지 않습니다.

이 문서는 당시 실패 기록입니다. 이후 같은 입력을 새 대화에서 재검증해 자동 재개와 등록 검사 통과를 확인했습니다. [후속 재검증](../2026-09-08-native-stop-recheck/README.md)은 별도로 기록하며 이 실패의 원문 판정은 유지합니다.

## 실행 조건과 관찰

- 모델 선택 표시: `Gemini 3.8 Flash High`, 실행 환경: `Local`입니다. 앱의 Application 설정에서 2.12.2를 확인했습니다.
- 기존 사용자 전역 설정을 상속했습니다. 전역 모델·권한 설정은 변경하지 않았으며 순수 v3 대조군은 아닙니다.
- 요청은 [정해진 시험 문구](prompt.txt) 한 번만 보냈습니다. 첫 응답에서 등록만 하고 자연 종료한 다음 훅이 재개시키면 실제 검사를 실행하는 연결 시험입니다. 거친 일반 요청의 품질 평가가 아닙니다.
- [사전 검사](preflight-tests.txt)에서 기존 레코드 회귀 검사 6개가 통과했습니다. 준비 중 기존 호출자 `app.py`를 누락한 실패도 발견했고 원본 해시가 일치하는 파일을 추가했습니다. [초기 준비 실패](preflight-missing-caller.txt).
- 네이티브 대화 이름은 `종료 훅 연결 시험`입니다. 첫 입력부터 마지막 응답까지 62초, 모델 응답 단계 21개, 도구 20회였습니다. 정확한 API 요청 수나 토큰 사용량은 아닙니다.
- 작업 등록 직후에는 `paused: 0`, `retries: 0`, 검사는 `pending`이었습니다. 자연 종료 후에는 `paused: 1`, `retries: 0`, 이유는 `호스트 중단 또는 오류`로 저장됐고 실행된 검사는 없었습니다.
- 새로고침한 Gemini 잔여 한도는 시험 전후 모두 주간 100%·5시간 99%였습니다. 반올림된 계정 표시이며 소비량 0을 뜻하지 않습니다. 크레딧 초과 사용은 꺼진 상태를 유지했습니다.

[관찰 요약](trace-summary.json), [입력·설치 조건](preparation.json), [당시 상태 DB](observed-state.sqlite3), [당시 설치 원문·입력·상태 스냅샷](snapshot.zip)을 보존했습니다. 숨은 사고 내용은 복사하지 않았습니다. 이 스냅샷에는 원래 설치 위치가 들어 있으며 원문 보존용입니다. 실제 Stop 입력이나 전역 환경 전체를 재현하는 자료는 아닙니다. 시험 후 프로젝트 플러그인은 제거 명령으로 보존 경로에 옮겼고 대화와 결과는 남겼습니다.

## 확인한 코드 결함과 보완

[공식 예시](https://antigravity.google/docs/hooks)는 `model_stop`을 보여 주지만, [저자가 직접 기록한 실행](https://atamel.dev/posts/2026/07-16_where_agy_hooks/)에는 `NO_TOOL_CALL`이 있습니다. 기존 코드는 후자를 중단으로 처리했습니다. 해당 입력의 재생 실패를 확인한 뒤 두 정상 종료 표현을 처리하도록 보완했습니다. 오류·백그라운드 작업·알 수 없는 종료 이유의 중단 처리는 유지합니다.

원본 Stop 입력이 저장되지 않아 **이번 실제 시험에 전달된 종료 이유는 확인하지 못했습니다.** 따라서 같은 원인이었다고 확정하지 않습니다. 새 버전은 활성 작업의 마지막 종료 메타데이터를 `continuation[].last_stop`에 저장합니다. 짧은 영문·숫자·밑줄 코드와 실행 번호·불리언 조건만 남기며 원문 프롬프트·오류 메시지는 저장하지 않습니다. 이전 이벤트의 원인을 소급해 만들어 넣지 않습니다.

[공개 입력의 로컬 재생](contract-replay.json)에서는 재개 결정 → 실제 회귀 검사 통과 → 종료를 확인했습니다. 이는 새 모델 요청이나 실제 호스트 실행이 아닙니다. [실패 당시 상태 사본의 마이그레이션](state-migration.json)에서도 기존 목표·중단·재개 횟수가 유지됐습니다.

보완 후 전체 로컬 검사 127개가 37.689초에 통과했습니다. [실행 로그](tests.log)와 [검증 당시 소스 해시](verification.json)를 함께 기록합니다.

이 실패 기록만으로는 원인을 확정하거나 해결을 주장할 수 없습니다. 후속 재검증은 저장된 종료 메타데이터와 모델의 재개 메시지·검증 실행을 대조한 별도 결과입니다. 장기 작업의 일반적 성공은 여전히 미검증입니다.
