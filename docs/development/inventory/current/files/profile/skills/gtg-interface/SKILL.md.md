# 화면 구현과 검증

현재 화면과 제품의 주요 작업을 확인하고 사용자가 어려워하는 지점을 구체화합니다. 기존 디자인 시스템과 컴포넌트가 있으면 따릅니다. 색·페이지 수·카드·모션을 미리 정한 템플릿으로 강제하지 않습니다. 정보의 우선순위와 사용자 동선에서 구조를 정합니다.

필요한 경로·로딩·빈 상태·오류·선택·복구 동작을 계획합니다. 복잡한 UI는 계획과 검증할 상태를 로컬 문서로 남깁니다. 모든 작은 수정에 장문 계획서를 요구하지 않습니다.

실제로 동작하는 인터랙션을 구현합니다. 가짜 지표·작동하지 않는 버튼·제품과 무관한 장식·일반적인 AI 홍보 문구를 넣지 않습니다. 문구는 사용자가 현재 상황과 다음 행동을 이해하도록 간결하게 작성합니다.

지원되는 브라우저나 앱 도구로 실제 화면과 동선을 확인합니다. 좁은 화면과 넓은 화면의 오버플로우, 키보드 이동·포커스, 읽기 순서, 직접 URL·뒤로가기, 감속 설정을 작업 범위에 맞게 점검합니다. 스크린샷 생성과 사람이 읽을 수 있는 화면 품질 확인은 구분합니다.

DOM의 단어·계획서 분량·페이지 수만으로 화면 품질을 판정하지 않습니다. 테스트와 실제 시각 관찰을 연결하고 도구가 없어 확인하지 못한 항목은 미검증으로 남깁니다.
