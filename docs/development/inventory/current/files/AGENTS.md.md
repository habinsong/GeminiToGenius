# GeminiToGenius 개발 지침

- 모든 설명은 한국어 존댓말로 작성합니다.
- 자동 목표 재개·컨텍스트 압축 뒤에는 `docs/development/current-work.md`를 먼저 읽고 실제 파일·실행·화면 상태와 대조합니다. 전체 범위는 `docs/development/README.md`, `docs/development/plan/roadmap.md`로 확인합니다.

- 사용자께서 기존 하네스의 전면 재개발과 불필요한 구현 제거를 승인하셨습니다. 사용자 변경은 보존하며, 제거 근거와 대체 동작을 기록합니다.
- 수정 전 `git status --short`, 관련 소스와 호출 경로를 확인합니다. 파일 전체 원문은 목록 문서에 보존하되 매 작업에서 관련 없는 코드를 모두 모델 컨텍스트에 넣지 않습니다.
- God-object를 만들지 않습니다. 코드 길이만이 아니라 책임과 의존성을 확인하고 CLI·도메인 상태·실행·저장·평가 준비·채점 책임을 분리합니다. 새 기능을 기존 대형 파일에 계속 누적하지 않습니다.
- 검증된 구현과 계획을 구분합니다. 규칙 문구·파일 개수·모의 입력 통과만으로 모델 품질이나 실제 플랫폼 호환성을 주장하지 않습니다.

- 불완전하거나 거친 자연어도 현재 맥락으로 구체화하여 수행합니다. 사용자가 `/` 명령이나 스킬 이름을 입력해야만 동작하는 구조를 만들지 않습니다.
- 실행 코어는 Gemini 모델 이름과 독립적으로 유지합니다. 출시 전 모델 사양을 추정하지 말고, 모델 설정이 꼭 필요할 때 공식 확인된 기능을 기준으로 처리합니다.
- 공개 웹 문서와 원본 소스는 비용 없는 조사 경로입니다. 출처 URL·확인일·적용 판단·검증 방법을 `docs/development/research`에 기록합니다.

- 승인 없이 커밋·푸시·공개 릴리스하지 않습니다. 전역 설치를 구현 검증에 사용하지 않고 임시 경로를 사용합니다.
