## 타사 하네스와의 비교 시험

동일한 문제 사례, 동일한 프롬프트, 동일한 채점기를 사용해 총 64회에 걸쳐 실제 비교 실행을 진행했습니다.

| 비교 그룹 | 자동 채점 건수 | 통과 건수 | 전회 통과율 |
|---|---|---|---|
| `agy` + GTG (Gemini 3.8 Flash High) | 14 | 14 | 7/7 |
| `agy` 기본 환경 (동일 모델) | 14 | 14 | 7/7 |
| Claude Code (Sonnet 5) | 14 | 12 | 6/7 |
| Codex CLI (gpt-5.6-terra) | 14 | 13 | 6/7 |

**동일 모델 조건에서 GTG 활성화 그룹과 비활성화 그룹의 통과율은 동일했습니다. 단일 턴 수준의 작업에서는 최종 산출물 품질 차이가 확인되지 않았습니다.** 모델이 16회 시도 중 5회에서만 작업을 등록했기 때문입니다. 실제 코드 실행을 거쳐야만 통과할 수 있는 난이도 높은 사례를 추가해 재시험했을 때도 두 그룹 모두 4/4로 결과가 같았으며, 해당 시험에서는 모델이 4회 모두 작업을 등록하지 않았습니다.

기존 7개 자동 채점 사례 중 6개는 4개 그룹 모두 전회 통과하여, 현재 평가 묶음의 변별력은 제한적입니다. 상세 내용은 [전체 비교 기록과 한계](../development/validation/2026-09-09-repeated-comparison/README.md)를 참고하세요.

Claude Code와 Codex는 기반 모델이 서로 다르므로, 이 결과로 하네스 제품 자체의 우열을 단순 비교할 수는 없습니다.

## 확인된 결함 및 해결 내역

실제 환경에서 직접 재현하고 수정한 결함만 기재합니다.

- 시스템 재부팅 후 이전 PID가 다른 프로세스에 재할당되었을 때 `recover`가 계속 거부되어 작업이 교착되던 문제를 해결했습니다. 프로세스 수명 중에만 유지되는 파일 잠금 방식으로 구조를 개편했습니다. [상세 기록](../development/validation/2026-09-09-reboot-recovery/README.md)
- 검사가 백그라운드에서 실행 중일 때 종료 훅이 작업 완료를 잘못 승인하던 문제를 수정했습니다. 비정상 중단된 실행의 잔여 기록도 동일 경로에서 격리하도록 보완했습니다. [상세 기록](../development/validation/2026-09-09-running-check-stop/README.md)
- 미실행 범위 보고 목록이 비어 있던 현상을 수정했습니다. 관측 범위에 단 하나의 셸 스크립트만 포함되어도 전체 결과가 `null`로 처리되던 로직을 개선했습니다. [상세 기록](../development/validation/2026-09-09-unobservable-scope/README.md)
- 평가 도구가 작업공간에 임시 설치된 GTG 자체 모듈 파일의 실행까지 "테스트 코드가 실행됨"으로 집계하여 GTG에 유리하게 편향되던 계측 오류를 바로잡았습니다.
