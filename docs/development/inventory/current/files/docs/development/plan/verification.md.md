# 검증 계획 및 평가 기준

## 검증 증거 수준 체계 (Evidence Levels)

| 수준 | 검증 대상 | 보증하는 내용 | 보증하지 않는 내용 |
| --- | --- | --- | --- |
| L0 | 정적 구조·문법·코드 카탈로그 | 필수 파일의 존재, 올바른 스키마, 기록의 최신성 | 실제 런타임 실행 성공 여부 |
| L1 | 실제 로컬 프로세스·상태 격리 테스트 | 프로세스 종료 코드, 타임아웃, 중단 복구, 패키지 설치 동작 | 실제 모델의 자율적 행동 품질 |
| L2 | 공식 계약 기반 이벤트 리플레이 | 규격화된 입출력 페이로드 파싱, 훅 응답, 로컬 부작용 격리 | 실제 호스트가 동일한 순서로 이벤트를 발행하는지 여부 |
| L3 | 제한된 실호스트 통합 점검 | 호스트의 훅 탐지, 스킬 호출, 도구 실행 결과의 모델 컨텍스트 전달 | 다양한 복합 과제에 대한 전반적 추론 성능 |
| L4 | 동일 조건 통제 벤치마크 평가 | 동일 과제 세트에서의 성공률, 토큰 비용, 소요 시간 비교 | 모든 도메인과 환경에서의 절대적 우월성 |

## 필수 회귀 테스트 시나리오

- 설치 전 무결성 검증 실패, 설치 도중 예외 복구, 기존 사용자 설정 파일 보존, 중복 재설치, 공백 및 비ASCII 문자 포함 경로 처리
- 규칙 원문 보존, 필수 훅 누락·중복·비활성화 및 비정상 타임아웃 단위 처리, 수동 이동된 설치본의 실패 감지와 자동 복구
- 훅의 빈 입력, 손상된 JSON, 필수 필드 누락, 부적합한 타입, 미지원 이벤트 수신 시 안전 처리
- 중복 이벤트 수신, 병렬 작업 충돌 방지, 프로세스 강제 중단 후 재개, 상태 데이터베이스 파일 손상 복구
- 실패한 검증, 만료된 성공 기록, 검증 이후 코드 수정 감지, 백그라운드 프로세스 잔존 시 완료 차단
- 사용자 명시적 취소, 외부 호스트 오류, API 쿼터 한도 도달, 동일 오류 반복 시 강제 재개 차단 여부
- 원시 대화 프롬프트, 환경 변수, 인증 토큰, 대형 도구 출력을 로그 파일에 복제하지 않는지 확인
- 인벤토리 카탈로그에서 바이너리, 개행 문자, 심볼릭 링크, 추가/삭제/수정 내역 및 민감 경로 격리 검증

## 모델 품질 비교 및 벤치마크 원칙

첫 번째 비교 시험은 동일한 Gemini 모델, 동일한 문제 세트, 동일한 쿼터 예산 조건 하에서 기본 프롬프트 환경과 GTG 플러그인 환경 간에 진행합니다. Codex, Claude Code, OmO 등 타사 도구와의 비교 시 기반 모델이 다를 경우 제품 스택 전체의 조합 비교로 명시하며, 하네스만의 단독 성능 개선으로 해석하지 않습니다.

`python3 -m evals.harness prepare`는 모델 호출 없이 시험용 디렉터리를 격리 구성하고, `grade` 명령은 디렉터리 외부의 고정된 채점 기준으로 산출물을 객관적으로 평가합니다. 함수의 반환값뿐만 아니라 기존 호출자 코드와의 호환성 및 보호 대상 파일 보존 여부를 함께 확인합니다. 수정 금지 지침이 포함된 과제의 경우 사람이 직접 검토하기 전까지 임의로 통과 처리하지 않습니다.

새 기능 추가 과제는 실제 Git 인덱스와 사용자 수정분을 사전 구성하여, 신규 기능 동작과 기존 포맷(JSON, CSV 등) 유지 여부를 함께 검증합니다. 채점 도중 소스 코드 변조나 오래된 바이트코드 캐시로 인한 허위 통과(`false positive`) 가능성도 사전에 차단합니다. 세부 과제 구성과 한계는 [평가 과제 및 한계](../../../evals/README.md) 문서를 참고하세요.

과제 세트는 사소한 버그 수정, 다중 파일 리팩터링, 회귀 테스트 작성, 기술 문서 조사, 비정상 실패 복구, UI 사용자 동선 검증 등 실제 현업 요청들로 구성합니다. 성공률, 미완료 오판율, 회귀 발생 여부, 불필요한 코드 변경량, 입출력 토큰 소모량, 도구 호출 횟수, 총 벽시계 시간을 종합 측정합니다.

실제 모델 평가는 대량 자동 실행을 지양합니다. L0~L2 수준의 로컬 검증을 먼저 완벽히 통과한 후, L3 수준에서 단일 작업으로 실호스트 연동을 확인합니다. 모델 API 호출 비용과 토큰량은 응답 메타데이터에 제공된 실제 수치만 기록하며, 추정치는 반드시 별도로 구분합니다.

## UI 및 화면 검증 기준

계획서나 코드 내 특정 단어의 존재 유무로 UI 검증을 통과시키지 않습니다. 요구사항에 명시된 사용자 동선, 로딩 상태, 빈 목록 처리, 오류 피드백, 폼 유효성 검사, 키보드 내비게이션, 포커스 제어, 반응형 레이아웃을 실제 브라우저 환경에서 직접 확인합니다. 페이지 분할 수, 컬러 팔레트, 카드 컴포넌트 배치는 제품 맥락에 따라 합리적으로 결정하며 일률적인 서식을 강제하지 않습니다.
