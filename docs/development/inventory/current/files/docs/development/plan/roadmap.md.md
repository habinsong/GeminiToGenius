# 재개발 계획 및 로드맵

최종 목표는 단일 자연어 요청만으로 관련 자료와 코드베이스를 깊이 있게 탐색하고, 복합 작업을 끝까지 완결하며, 실패를 자율 복구하고, 그 결과를 객관적 실행 증거로 입증하는 에이전트 하네스를 구축하는 것입니다. 타사 도구 대비 우수성 여부는 동일한 작업, 모델, 예산, 채점 조건 하에서 수행된 엄격한 비교 결과만을 근거로 판단합니다.

슬래시 명령어나 정교한 프롬프트 엔지니어링, 수동 스킬 선택을 사용자에게 요구하지 않습니다. 불완전하거나 거친 요청이라도 현재 저장소 상태, 오류 로그, UI 화면, 직전 대화 맥락을 기반으로 구체화합니다. 사용자의 본래 목적이나 데이터 안전을 변경할 수 있는 치명적 모호성에 대해서만 질문하며, 독립적인 조사와 준비 작업은 선제적으로 진행합니다. 상세 작업 명세와 완료 조건은 에이전트가 직접 작성하며, 사용자는 일상적인 자연어로 작업할 수 있습니다.

## 우선 폐기한 안티패턴

- 훅 파일 개수나 문서 내 특정 키워드의 존재 유무만으로 기능 동작을 단정하는 형식적 검증
- 단순 작업에 대해서도 전체 코드 강제 정독, 장문 계획서 작성, 무조건적인 다중 페이지 분할을 강제하던 과도한 프롬프트 규칙
- 설치 디렉터리를 먼저 변경하고 사후에야 동작을 검증하던 불안정한 배포 방식과 분산된 중복 사본
- 실질적 검증 없이 무분별하게 스킬과 훅을 늘리거나, 매 턴마다 LLM 심사자를 호출해 비용을 가중시키던 비효율적 구조

UI 결과물의 맥락, 시각적 위계, 웹 접근성, 실제 사용자 동선 검증은 유지하되, 디자인 품질 평가를 단순 정규식 문구 검사로 대체하지 않습니다.

## 작업 단위 및 개발 원칙

모든 개발 단계는 [실패 재현 → 신규 구현 → 직접 검증 → 문서 및 카탈로그 갱신]의 수명주기를 따릅니다. 기존 기능을 삭제할 때는 이를 대체할 안정적인 경로와 회귀 테스트 증거를 사전에 확보해야 합니다. 세부 구현 현황은 [진행 기록](../status.md)에 구체적인 파일, 실행 명령, 결과 데이터와 함께 기록합니다.

공식 기술 문서 조사는 상시 갱신합니다. 자료의 신뢰성은 검색 엔진 노출 순위가 아닌 공식 벤더 문서, 원본 소스 코드, 최종 확인 일자를 기준으로 평가합니다. 실제 LLM API 호출은 로컬 환경에서 검증할 수 없는 필수 런타임 호환성 확인에만 선별적으로 사용하며, 무의미한 대량 반복 평가는 지양합니다.
