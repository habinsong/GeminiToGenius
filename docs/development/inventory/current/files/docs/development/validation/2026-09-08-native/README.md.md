2026-09-08, Antigravity 2.11.0에서 모델 선택 표시가 `Gemini 3.8 Flash High`인 상태로 실행했습니다. 요청은 한 번만 보냈으며 후속 요청이나 반복 평가는 하지 않았습니다.

> 중복된 항목 합치면 값이 자꾸 사라짐. 고쳐줘.

앱의 프로젝트 이름은 `GTG 단일 검증 2026-09-08`, 대화 제목은 `데이터 중복 합치기 오류`입니다. 격리된 임시 폴더에서 수행했고 기존 사용자 전역 설정을 상속했습니다. 전역 설정이나 권한, 모델 선택, 크레딧 초과 사용 설정은 바꾸지 않았습니다.

## 결과

- 네이티브 기록에서 `SYSTEM_SDK`의 GTG 초기 메타데이터 주입을 확인했습니다.
- 모델의 첫 도구 호출은 새 `gtg-build/SKILL.md` 읽기였으며 실제 스킬 본문이 반환됐습니다. 슬래시나 스킬 이름을 프롬프트에 넣지 않았습니다.
- 모델은 `records.py`, `test_records.py`만 수정했습니다. 필드 보존·최종 값 우선·순서 유지·입력 보존·ID 0·누락 ID의 오류 처리를 구현했습니다.
- 후보의 단위 테스트 6개를 독립적으로 다시 실행해 통과했습니다. [출력](candidate-tests.txt).
- 작업 폴더 밖의 검사 8개가 통과했고 보호 파일·평가 기준은 유지됐습니다. [채점 결과](grade.json).
- 실제 기록의 첫 사용자 입력부터 마지막 모델 응답까지 74초였습니다. 모델 응답 단계는 22개, 도구 호출은 21개였습니다. API 요청 수나 정확한 토큰 사용량과 동일하다고 가정하지 않습니다.
- 실행 전 잔여 한도는 주간 100%·5시간 100%, 실행 후에는 주간 100%·5시간 99%로 표시됐습니다. 반올림된 계정 표시이며 개별 요청의 정확한 소비량이 아닙니다.

이 단순 수정에서는 영속 작업을 등록하지 않았습니다. 따라서 실제 `Stop` 재개·장기 상태 복구를 검증한 사례는 아닙니다. 기존 전역 설정이 함께 적용됐으므로 순수 v3 대조군도 아니며, 단일 사례로 일반 품질·다른 모델·경쟁 우위를 주장하지 않습니다.
