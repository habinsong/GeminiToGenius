# 완료 증명서

작업 완료를 보고할 때 완료 주장과 검증 근거를 단일 파일에 결합합니다. 검증 결과를 전달받는 측은 별도 상태 데이터베이스 없이 이 파일만으로 결과를 독립 재현할 수 있습니다.

```bash
python3 "$GTG" certify TASK_ID --output .gtg/certificate.json
python3 "$GTG" replay --certificate .gtg/certificate.json --workspace .
```

## 증명서 구성 요소

각 완료 조건마다 실제로 실행한 명령, 종료 코드, 검증 대상 파일의 SHA-256 지문이 기록됩니다. 성공하지 못한 검사에는 지문을 첨부하지 않습니다. 아직 미검증 상태인 작업을 `certify`하면 종료 코드 1과 함께 `verified: false`가 반환됩니다.

본문 전체에 걸쳐 무결성 `digest`가 포함되어 있으므로, 증명서 내용이 한 글자라도 변조되면 `replay`가 실행을 거부합니다.

## `replay` 판정 체계

`replay`는 증명서와 현재 파일 상태만을 사용합니다. 명령을 다시 실행하여 종료 코드 0과 기록된 파일 지문이 모두 동일하게 재현될 때만 `reconstructed: true`로 판정합니다.

| 판정 | 종료 코드 | 설명 |
|---|---|---|
| `pass` | 0 | 모든 검증 명령이 성공적으로 재현되었으며 검사 범위도 완전합니다. |
| `invalid` | 1 | 재현 검증에 실패했습니다. 증명서가 현재 작업공간 상태를 뒷받침하지 못합니다. |
| `inconclusive` | 2 | 명령은 재현되었으나, 관측할 수 없는 파일 등으로 인해 미확인 범위가 남았습니다. |

**`inconclusive`를 성공(`pass`)으로 왜곡하여 보고하지 않습니다.** 파일 내용이 변경되어 재현이 깨진 경우에는 `reason: "fingerprint"` 사유가 기록됩니다.

증명서에 기록된 원래 작업공간과 다른 디렉터리에서 실행할 때는 명령 내용을 직접 검토한 뒤 `--trust-commands` 플래그를 전달해야 합니다.

## 확인하지 못한 범위 (미검증 스코프)

증명서에는 검증의 사각지대를 투명하게 밝히는 추가 필드가 포함됩니다.

- `unverified_scope`: 통과한 검사가 존재함에도 **어떤 검사에서도 실제로 호출되지 않은** 검증 대상 파일 목록입니다.
- `coverage_complete`: `false`인 경우 위 목록은 최소한의 하한선일 뿐입니다. 비어 있는 목록을 "모든 코드가 100% 검증됨"으로 해석해서는 안 됩니다.
- `unobservable_scope`: 런타임 추적이 불가능하여 위 판단을 가로막은 파일입니다. 셸 스크립트나 Go·Rust처럼 실행 흐름을 직접 추적할 수 없는 코드가 검증 범위에 포함되면 여기에 명시됩니다.

관측 가능한 런타임과 제한 사항은 [실행 관측](../architecture/coverage.md) 문서를 참고하세요.

## 증명서의 한계와 비보증 범위

이 증명서는 사전에 등록된 검사 범위 안에서 결과가 재현 가능함을 증명할 뿐입니다. 등록된 검사가 사용자의 요구사항을 완전히 포괄하는지까지 증명하지는 않습니다. 따라서 완료 보고서에는 증명서 판정 결과를 있는 그대로 명시하고, 검증 명령 설계의 타당성은 별도로 소통해야 합니다.
