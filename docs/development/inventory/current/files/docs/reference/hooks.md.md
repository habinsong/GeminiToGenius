# 훅 계약

GTG는 호스트가 매 턴마다 호출하는 두 개의 플랫폼 훅을 기반으로 동작합니다. 훅 내부에서 모델을 재호출하거나 테스트를 임의로 자동 실행하지 않습니다. 오직 저장된 작업 상태를 읽어 객관적인 사실 데이터만 응답합니다.

| 호스트 | 턴 시작 이벤트 | 턴 종료 이벤트 |
|---|---|---|
| `antigravity` (데스크톱·IDE) | `PreInvocation` | `Stop` |
| `antigravity-cli` (`agy`) | `PreInvocation` | `Stop` |
| `gemini-cli` | `BeforeAgent` | `AfterAgent` |

호스트마다 식별 필드 규격도 다릅니다. Antigravity 계열은 `conversationId`, `workspacePaths`를 사용하며, Gemini CLI는 `session_id`, `cwd`를 사용합니다. 타임아웃 단위 또한 전자는 초, 후자는 밀리초 기준입니다. 이러한 플랫폼별 차이는 [`gtg/platforms.py`](../../gtg/platforms.py) 단 한 곳에서 통합 관리합니다.

## 턴 시작 훅 동작

세션 최초 호출 시에는 확인된 호스트 환경, 세션 식별자, 작업공간 경로 정보를 컨텍스트 메시지로 주입합니다. 모델이 작업을 등록할 때 이 값을 참조하도록 하기 위함이며, 프롬프트 지시가 아닌 경로 데이터임을 명시합니다. 현재 작업공간에 이어서 진행할 수 있는 기존 작업이 존재하면 후보 목록으로 함께 안내하되, 모델이 임의로 자동 선택하지는 않습니다.

이미 미검증 작업이 연결되어 있는 경우에는 직전 검사 결과 내역을 함께 전달합니다.

## 턴 종료 훅 동작

턴 종료 시점에 미검증 상태가 남아 있다면 남은 재개 예산 내에서 세션을 한 번 더 지속시킵니다. 기본 2회, 최대 상한은 8회입니다. 자동 재개는 사용자의 모델 쿼터를 소모하므로 단순한 작업에서 무분별하게 상한을 늘리지 않습니다.

다음 조건에서는 세션을 강제로 되돌리지 않고 종료를 승인합니다.

- 종료 원인이 정상 완료(`model_stop`, `NO_TOOL_CALL`)가 아니거나 예외 오류가 동반된 경우
- `fullyIdle` 상태가 아니어서 아직 백그라운드 작업이 실행 중인 경우
- 동일한 턴 종료 이벤트가 중복 수신된 경우 (최초 1회만 카운트)
- **검증 명령이 아직 실행 중인 경우.** 이 때는 세션을 억지로 재개하지 않고, 어떤 검사가 진행 중인지와 프로세스 복구 방법을 종료 사유에 명시합니다. 미검증 상태를 정상 완료로 허용하지 않습니다.
- 최대 재개 상한에 도달한 경우. 종료 사유와 설정된 예산 한도를 기록하고 연결을 종료합니다.

## 장애 격리 및 안전 처리

훅은 내부에서 예외가 발생하더라도 항상 유효한 JSON을 반환하며 종료 코드 0으로 완료되도록 설계되어 있습니다. 저장소 상태를 읽지 못한 경우 세션 종료 자체를 막지는 않되, "이번 턴에는 완료 조건이 정상 적용되지 않았음"을 모델에 명확히 알립니다. 응답을 비워둘 경우 모델이 검증이 통과된 것으로 오판할 위험이 있기 때문입니다.

입력 페이로드 형식이 호스트 규격과 어긋나는 경우에는 플랫폼 수준의 불일치로 간주하여 조용히 처리합니다. 원시 사용자 입력 내용이나 민감한 세션 키는 로그에 남기지 않습니다.

## 호스트별 규격 검증 및 한계

Antigravity `Stop` 이벤트의 출력 스키마는 공식 문서상 `decision`과 `reason` 두 필드만 정의되어 있으며, `reason`은 `decision`이 `"continue"`일 때만 모델 컨텍스트에 주입된다고 명시되어 있습니다. 종료(`"approve"`)를 허용하는 응답에 함께 전달한 `reason`이 모델이나 사용자에게 실제로 표시되는지는 공식 문서에 기재되어 있지 않아 **실증적으로 확인되지 않았습니다.** 필드값은 규격대로 채워 반환하지만 표시 여부를 단정하지는 않습니다.

Gemini CLI의 경우, `systemMessage`가 `decision`이나 `continue` 여부와 무관하게 콘솔로 출력되는 경로를 소스 코드로 확인했습니다. 따라서 작업 종료를 막지 않으면서도 사용자 터미널에 메시지를 출력할 수 있습니다. 다만 이는 대화형 터미널 화면에만 표시되며 모델의 컨텍스트 버퍼에는 주입되지 않습니다.

`agy` 헤드리스 실행 시 `--add-dir`을 지정하지 않으면 `workspacePaths`가 빈 배열로 전달됩니다. 이 경우 GTG는 작업공간을 특정할 수 없어 어떤 개입도 하지 않습니다.
