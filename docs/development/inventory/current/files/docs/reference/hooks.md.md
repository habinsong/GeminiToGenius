# 훅 계약

GTG는 호스트가 매 턴 부르는 훅 두 개로 동작합니다. 훅 안에서 모델을 부르거나 테스트를 자동 실행하지 않습니다. 저장된 상태를 읽어 사실만 돌려줍니다.

| 호스트 | 턴 시작 | 턴 종료 |
|---|---|---|
| `antigravity` (데스크톱·IDE) | `PreInvocation` | `Stop` |
| `antigravity-cli` (`agy`) | `PreInvocation` | `Stop` |
| `gemini-cli` | `BeforeAgent` | `AfterAgent` |

식별 필드도 다릅니다. Antigravity 계열은 `conversationId`·`workspacePaths`, Gemini CLI는 `session_id`·`cwd`를 씁니다. 시간 제한 단위는 앞이 초, 뒤가 밀리초입니다. 이 차이는 [`gtg/platforms.py`](../../gtg/platforms.py) 한 곳에만 적혀 있습니다.

## 턴 시작에 하는 일

첫 호출이면 확인된 호스트·세션·작업공간 값을 임시 메시지로 전달합니다. 모델이 작업을 등록할 때 이 값을 쓰라는 뜻이고, 지시가 아니라 경로 데이터라고 명시합니다. 이어갈 만한 저장된 작업이 있으면 후보로 함께 알립니다. 자동으로 고르지는 않습니다.

미검증 작업이 연결돼 있으면 현재 검사 결과를 함께 전달합니다.

## 턴 종료에 하는 일

미검증 상태가 남아 있으면 남은 예산 안에서 한 번 되돌립니다. 기본 2회, 상한 8회입니다. 자동 재개는 사용자 쿼터를 쓰므로 짧은 작업에서는 올리지 않습니다.

되돌리지 않는 경우가 있습니다.

- 종료 이유가 정상 종료(`model_stop`, `NO_TOOL_CALL`)가 아니거나 오류가 붙어 있으면 멈춥니다.
- `fullyIdle`이 아니면 백그라운드 작업이 남은 것이므로 손대지 않습니다.
- 같은 종료 이벤트가 반복되면 한 번만 셉니다.
- **검사가 아직 실행 중이면 재개하지 않습니다.** 대신 어떤 검사가 남았는지와 복구 방법을 종료 사유에 적습니다. 미검증인데 조용히 종료를 허용하지는 않습니다.
- 상한에 닿으면 이유와 실제 예산 값을 남기고 연결을 멈춥니다.

## 실패했을 때

훅은 어떤 오류에서도 유효한 JSON을 내고 종료 코드 0으로 끝냅니다. 상태를 읽지 못하면 종료를 막지 않고, 대신 "이번 턴에는 완료 조건이 적용되지 않았다"는 사실을 알립니다. 조용히 비우면 모델이 검증이 걸린 줄 알기 때문입니다.

입력 형식이 어긋나는 것은 호스트 계약의 문제로 보고 조용히 넘깁니다. 원문 입력이나 세션 값은 로그에 남기지 않습니다.

## 확인한 것과 못 한 것

Antigravity `Stop`의 출력 필드는 공식 문서상 `decision`과 `reason` 둘뿐이고, `reason`은 `decision`이 `"continue"`일 때만 대화에 주입된다고 적혀 있습니다. 종료를 허용하는 응답에 실은 `reason`이 전달되는지는 문서에 없어 **확인하지 못했습니다.** 값은 넣되 전달을 주장하지 않습니다.

Gemini CLI는 `systemMessage`가 `decision`·`continue`를 보지 않는 경로에서 발행되는 것을 저장소 원본 코드로 확인했습니다. 종료를 막지 않고 사용자 화면에 표시됩니다. 다만 대화형 터미널에서만 보이고 모델 컨텍스트에는 들어가지 않습니다.

`agy` 헤드리스 실행에서는 `--add-dir` 없이 `workspacePaths`가 빈 배열로 옵니다. 그 상태에서 GTG는 아무 일도 하지 않습니다.
