# 명령 목록

설치된 패키지 디렉터리의 `run.py`가 전체 CLI의 진입점입니다. 모델이 이 명령을 직접 호출하며, 사용자가 직접 입력할 필요는 없습니다. 아래 예시의 `$GTG`는 설치된 `run.py`의 절대 경로입니다.

```bash
GTG=~/.gemini/config/plugins/geminitogenius/run.py
```

모든 작업 관리 명령은 `--workspace` 옵션을 지원합니다. 생략하면 현재 작업 디렉터리를 기준으로 동작합니다. 전역 옵션 `--state`로 상태 데이터베이스 경로를 직접 지정할 수 있으며, 두 옵션이 함께 전달되면 `--state`가 우선합니다.

## 작업 관리

| 명령 | 역할 |
|---|---|
| `start --spec <파일>` | 완료 조건이 고정된 새 작업을 생성합니다. `--platform`, `--session`을 지정하면 해당 호스트 세션에 연결합니다. |
| `tasks` | 저장된 작업 목록, 메모, 세션 연결 후보를 읽기 전용으로 조회합니다. 기록된 상태가 없으면 빈 목록을 반환합니다. |
| `attach <작업ID> --platform <호스트> --session <세션>` | 기존 작업을 현재 활성 세션으로 전환 연결합니다. 이전 검사 결과와 메모는 그대로 보존됩니다. |
| `status <작업ID>` | 지정된 작업의 현재 검사 결과, 작업 명세, 진행 메모를 조회합니다. |
| `checkpoint <작업ID> --note <파일>` | 작업 재개용 메모를 저장합니다. 단, 메모 저장이 검사 통과를 대체하지는 않습니다. |

## 검증 실행

| 명령 | 역할 |
|---|---|
| `verify <작업ID>` | 등록된 검증 명령들을 순차 실행하며, 첫 번째 실패 시 즉시 중단합니다. |
| `verify <작업ID> --all` | 일부 검사가 실패하더라도 등록된 모든 검증을 끝까지 실행합니다. |
| `verify <작업ID> --check <검사ID>` | 지정된 특정 검사만 선별 실행합니다. 결과는 `requested_verified` 필드에 별도 표시됩니다. |
| `recover <작업ID>` | 비정상 중단된 검사의 잔여 실행 기록을 정리합니다. 해당 검사 프로세스가 여전히 살아 있다면 정리를 거부합니다. |

## 완료 증명서 및 재현

| 명령 | 역할 |
|---|---|
| `certify <작업ID> --output <파일>` | 완료 주장과 실제 실행 명령, 종료 코드, 파일 지문을 단일 증명서 파일로 패키징합니다. 미검증 상태라면 종료 코드 1을 반환합니다. |
| `replay --certificate <파일>` | 증명서 파일만 읽어 검증 명령을 다시 실행합니다. 로컬 상태 DB에 의존하지 않습니다. |

`replay`의 종료 코드는 증명서 판정 결과와 일치합니다. `0`은 `pass`(재현 성공 및 범위 완전), `1`은 `invalid`(재현 실패 또는 불일치), `2`는 `inconclusive`(재현되었으나 미확인 범위 잔존)를 나타냅니다.

## 기타 유틸리티

| 명령 | 역할 |
|---|---|
| `inspect <경로...>` | 여러 텍스트 파일을 한 번에 읽고 라인 범위, 잘림 여부, 파일 해시를 함께 반환합니다. |
| `pause --platform <호스트> --session <세션> --reason <사유>` | 사용자 명시적 확인 대기나 외부 리소스 한도로 인해 작업을 일시 정지할 때 사용합니다. |
| `resume --platform <호스트> --session <세션>` | 일시 정지되었던 세션 연결을 다시 활성화합니다. |

## 플랫폼 훅

호스트 환경이 `hook <호스트> <이벤트>` 규격으로 호출합니다. 표준 입력(stdin)으로 호스트 이벤트 페이로드를 전달받고 표준 출력(stdout)으로 처리 결과 JSON을 응답합니다. 사용자가 수동으로 호출하지 않습니다. 세부 계약은 [훅 계약](hooks.md) 문서를 참고하세요.
