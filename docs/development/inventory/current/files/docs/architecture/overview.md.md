# 구조

GTG는 두 조각으로 나뉩니다. 호스트가 부르는 **훅**과, 훅이 읽는 **로컬 실행 코어**입니다. 코어는 모델도 네트워크도 쓰지 않습니다. Python 표준 라이브러리만으로 작업, 완료 조건, 명령 증거, 중단 이유를 다룹니다.

```
호스트(Antigravity / agy / Gemini CLI)
   │  훅 이벤트
   ▼
gtg/hooks.py ──▶ gtg/sessions.py ──▶ gtg/store.py  (SQLite + 실행 잠금)
   │                                      ▲
   │                                      │
   └── 안내 문구 gtg/context_message.py    │
                                          │
모델이 부르는 명령 ──▶ gtg/runner.py ──────┘
                          │
                          ├─ gtg/spec.py       계약 검증, 파일 지문, 범위 예산
                          ├─ gtg/coverage.py   실제 실행한 파일 관찰
                          └─ gtg/certificate.py 증명서 생성과 재실행
```

## 경계를 나눈 이유

인증, 모델 호출, 샌드박스는 호스트가 합니다. GTG는 거기에 끼어들지 않습니다. 호스트마다 다른 것은 이벤트 이름, 식별 필드, 설치 경로, 시간 단위 넷뿐이고 전부 [`gtg/platforms.py`](../../gtg/platforms.py)에 모여 있습니다. 호스트를 하나 더 지원하려면 그 파일에 줄을 더하면 됩니다.

평가 코드는 제품 코드를 가져오지 않습니다. 채점에 표준 라이브러리만 써서, 제품 구현을 바꾸면 채점 기준까지 따라 바뀌는 일이 없게 했습니다. 이 분리는 시험으로 고정돼 있습니다.

모델 ID로 분기하지 않습니다. 호스트가 고른 모델을 그대로 씁니다. 확인하지 못한 모델의 사고 수준이나 토큰 한도를 추정하지 않습니다.

## 모듈 책임

모듈 하나가 여러 책임을 갖지 않도록 경계를 문서에 고정하고, 실제 파일과 어긋나면 검사가 실패합니다. 전체 표는 [모듈 책임](../development/plan/architecture.md#모듈-책임)에 있습니다.

## 상태

작업공간의 `.gtg/state.sqlite3` 하나입니다. 폴더는 `0700`, 파일은 `0600`으로 만들고 `.gitignore`를 함께 넣어 사용자 저장소의 추적 목록에 나타나지 않게 합니다.

한 작업에 실행 중인 검사는 하나뿐이라는 것을 유니크 인덱스로 강제합니다. 실행 중인지 여부는 PID가 아니라 실행하는 동안만 유지되는 파일 잠금으로 판단합니다. PID는 재부팅하면 다시 배정되고 같은 부팅 안에서도 재사용되므로 신원이 되지 못합니다. 잠금은 OS가 프로세스 종료 시 풀어 주므로 정상 종료, 강제 종료, 전원 차단, 재부팅을 한 방식으로 덮습니다. 검사 프로세스가 잠금을 물려받기 때문에 소유자만 죽고 검사가 남은 경우도 같은 신호로 드러납니다.

## 설치

하나의 원본에서 호스트별 패키지를 만듭니다. 설치 전에 별도 폴더에서 검증하고, 파일 이동을 미리 기록한 뒤 옮깁니다. 도중에 프로세스가 죽으면 다음 실행이 그 기록을 보고 정리합니다.

패키지에는 파일 해시 목록이 들어갑니다. 배포된 지시문이 바뀌면 검증이 거부합니다. 지시문에 제어 문자나 방향 제어 문자, 폭 없는 문자가 들어가는 것도 거부합니다.
