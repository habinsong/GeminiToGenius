# 실행 관측

검증 명령을 실행할 때 실제로 어떤 코드 파일이 호출되었는지 런타임 수준에서 추적하여 함께 기록합니다. 통과한 검증이 실제로는 어떤 대상 코드를 실행조차 하지 않았는지 투명하게 드러내기 위함입니다.

## 추적 메커니즘

Python 환경에서는 임시 디렉터리에 생성한 `sitecustomize.py`를 `PYTHONPATH` 최우선 순위에 배치하여 인터프리터 부트스트랩 시점에 계측을 시작합니다. Python 3.12+에서는 `sys.monitoring`의 `PY_START` 이벤트만 청취하며, 최초 콜백 시 즉시 `DISABLE`을 반환하므로 이미 한 번 진입한 코드 위치는 추가 오버헤드 없이 계측이 꺼집니다. `sys.monitoring`을 지원하지 않는 환경에서는 `sys.settrace` 기반으로 안전하게 폴백합니다.

Node.js 환경에서는 `--require` 플래그로 부트스트랩 스크립트를 주입하고 `module.registerHooks`의 `load` 이벤트를 가로채 실제로 로드 및 실행된 파일들을 수집합니다.

검증 명령이 내부에서 생성한 자식 프로세스(Subprocess) 역시 동일한 환경 변수를 상속받아 일관되게 관측됩니다.

사용자 환경의 기존 `sitecustomize`를 덮어쓰거나 가리지 않습니다. 잔여 검색 경로에서 기존 원본을 탐색해 순차적으로 실행하며, 관측기 내부에서 관측기가 중첩 실행되더라도 사용자 파일 추적을 건너뛰지 않습니다.

## 지원 런타임 및 확장자

| 확장자 | 관측 지원 상태 |
|---|---|
| `.py`, `.js`, `.mjs`, `.cjs` | 기본적으로 완전 관측을 지원합니다. |
| `.ts`, `.mts`, `.cts` | 런타임(Node.js 등)이 직접 소스를 실행할 때만 관측합니다. |
| `.tsx`, `.jsx`, `.go`, `.rs`, `.sh` 등 | 직접 관측 대상에서 제외됩니다. |

TypeScript의 경우 초기에는 관측 불가로 분류했으나, Node.js 최신 런타임이 `.ts` 파일을 트랜스파일 없이 직접 실행하고 훅이 해당 소스 경로를 정상 캡처함을 실측으로 확인하여 지원 대상에 포함했습니다. 다만 사전에 빌드된 컴파일 산출물(dist/build)을 실행한 경우에는 원본 TypeScript 소스가 미실행된 것으로 단정하지 않습니다.

셸 스크립트는 의도적으로 관측 대상에서 배제했습니다. `BASH_ENV`와 `DEBUG` 트랩 조합으로는 `source`로 호출된 내부 스크립트를 안정적으로 추적하기 어렵고, 이를 해결하려면 사용자 스크립트의 실행 동작을 변경하는 옵션을 강제해야 하기 때문입니다. 또한 기본 `/bin/sh`는 `BASH_ENV` 자체를 무시합니다. 불완전한 부분 관측은 실제로 실행된 파일을 미실행 상태로 잘못 보고할 위험이 있으므로, 애초에 관측 불가능(`unobservable`)으로 명시하는 방식을 택했습니다.

## 산출 메트릭 필드

| 필드명 | 의미 |
|---|---|
| `executed_watch` | 해당 검증 명령 실행 중 실제로 호출된 검사 대상 파일 목록 |
| `unexecuted_watch` | 검증은 통과했으나 실제로는 단 한 번도 실행되지 않은 검사 대상 파일 목록 |
| `unobservable_watch` | 런타임 제약으로 인해 실행 여부를 판단할 수 없었던 파일 목록. 셸 스크립트 하나만 포함되어도 전체 판단이 보류됩니다. |

`unexecuted_watch`가 `null`인 경우는 두 가지입니다. 관측 불가능한 언어가 범위에 포함되어 있거나, 대상 파일 수가 너무 많아 전수 조사가 제한된 경우입니다. 전자의 경우에만 `unobservable_watch`에 해당 파일 목록이 채워집니다. 검증 명령을 언어별로 분리하여 관측 가능한 범위만 선별 등록하면, 나머지 코드에 대한 정확한 미실행 목록을 확보할 수 있습니다.

## 한계와 해석 기준

실행 관측은 파일 단위로만 이루어집니다. 파일이 실행되었다는 사실이 해당 파일의 모든 코드 라인이나 로직 분기가 검증되었음을 뜻하지는 않으며, 코드 커버리지(라인/브랜치 커버리지)를 대체하지 않습니다. 또한 동일한 코드 내용을 다른 경로에 복사해 실행한 경우 원본 파일은 미실행으로 판정됩니다. 문서나 설정 파일 같은 비실행 정적 파일은 관측 대상이 아닙니다.
