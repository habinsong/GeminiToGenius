# 부분 완료 작업의 실제 재개 검증

**새 세션에서 기존 미완료 작업을 찾아 연결하고 남은 CSV 구현을 완료했습니다.** 요청은 `아까 하던 거 이어서 끝내줘. 내가 바꾼 파일명은 그대로 두고.` 한 번이며 슬래시·작업 ID·실행 명령을 넣지 않았습니다.

## 입력과 독립 판정

`resume-export`는 CSV 직렬화가 끝났지만 다운로드 연결이 남은 작은 Python 작업입니다. 이전 검사의 실제 통과 기록·메모·중단 연결과 더 최근에 완료된 다른 작업을 준비했습니다. 이 이전 이력은 평가 준비 코드가 생성했으며 실제 모델이 앞선 세션에서 작성한 이력은 아닙니다. 사용자가 바꾼 파일명 `현장 기록`은 커밋 없는 Git 인덱스 위의 실제 diff입니다.

[준비 기록](preparation.json)과 [초기 채점](initial-grade.json)은 기능 실패·보존 범위 통과입니다. 실행 직전 원본 파일 해시 전체가 일치했습니다. 모델은 준비된 작업 폴더만 제공받았고 평가 기준은 그 밖에 뒀습니다.

- [독립 최종 채점](final-grade.json): 8개 결과 검사 통과, 변경은 `app.py` 하나, 범위 위반 없음입니다. CSV·기존 JSON·공개 호출자·키워드 인자·사용자 파일명을 확인했습니다.
- [최종 상태](final-status.json): 의도한 기존 작업 ID에 실제 새 세션이 연결됐으며 `verified: true`입니다. 이전 작업 2개·연결·검증·메모의 모든 행이 그대로 남았습니다. 새 작업은 만들지 않았습니다.
- [상태 전](state-before.sqlite3)·[상태 후](state-after.sqlite3): 이전 serializer 검사와 완료된 비교 작업은 보존됐고 새 serializer·download 검사가 추가됐습니다. 과거 메모를 남긴 채 완료 메모를 추가했습니다.
- [후보 변경](candidate.diff): 사용자 파일명과 Git 인덱스·HEAD 상태를 보존했습니다. 파일 자동 복원이나 커밋은 하지 않았습니다.

## 실제 호출 순서와 한도

[도구 기록](native-tools.json)에서 단계 3의 `gtg-build` 읽기 → 17의 `tasks` → 21의 원래 작업 `status` → 25의 `attach` → 64의 등록 검사 → 72의 메모 저장을 확인했습니다. [추출 스크립트](capture_native.py)는 해당 대화 DB에서 시각과 도구 인자만 읽습니다. 모델 응답·숨은 사고 본문은 복사하지 않습니다. 이 버전의 관측용 파서이며 제품 API가 아닙니다.

호스트는 Antigravity 2.12.2입니다. 대화 ID는 `55bff795-2bca-4449-ac1e-77d0a5be9f59`, 모델 선택 표시는 `Gemini 3.8 Flash High`, 환경은 `Local`입니다. 전역 사용자 규칙·스킬과 권한 설정을 상속했습니다. 사용자 입력부터 마지막 응답까지 117.397초, 모델 응답 단계 33개·도구 32회입니다. 추론 요청 수나 정확한 토큰 소비량은 아닙니다.

이번 요청 1회로 전체 실제 시험 요청은 누적 4회입니다. 새로고침한 Gemini 잔여 한도는 시험 전 주간·5시간 100%, 시험 후 주간 100%·5시간 99%입니다. 자동 재개는 필요하지 않았고 최종 종료는 `NO_TOOL_CALL`, `fully_idle: true`, 오류 없음입니다. [관측 요약](trace-summary.json).

원본 폴더 선택 중 열기 버튼이 일시 비활성화됐으나 이후 같은 원본 폴더를 정상 연결했습니다. 원인은 확정하지 않았습니다. 임시 Quick Start 프로젝트의 빈 폴더 연결을 해제하고 평가 폴더 하나만 남긴 뒤 요청했습니다. 시험 후 임시 플러그인을 제거 명령으로 보존 경로에 옮겼습니다. 대화와 결과는 유지했고 전역 설정은 변경하지 않았습니다.

## 유지보수 변경과 남은 낭비

평가의 CLI·정의·작업공간·준비·진행 상태 생성·채점을 책임별 모듈로 분리했습니다. 이전 Python 호출과 두 CLI 진입점은 유지하며 모든 평가 모듈을 정의 해시에 포함합니다. 신규 재개 검사 4개를 포함한 전체 145개 검사가 54.512초에 통과했습니다. [로그와 해시](verification.json).

실제 모델은 미설치 `gtg` 명령을 찾았고 `status`에 지원하지 않는 `--workspace`를 붙였습니다. 이후 스스로 올바른 호출로 복구했습니다. 이를 근거로 스킬 본문에 설치 실행기 위치를 명시하고 명령별 인자를 설명했습니다. 새 명령·의존성·추상화는 추가하지 않았습니다.

이 안내 변경 후 패키지 검사 10개와 두 호스트 패키지의 실행기 경로·`tasks`·`status --help`를 직접 확인했습니다. [안내 검증](runner-guidance-check.json). 공용 스킬 검사기는 기본·번들 Python 모두 `PyYAML`이 없어 실행하지 못했습니다. 저장소의 frontmatter·패키지 검증은 통과했습니다. 안내 수정의 실제 모델 행동 개선은 다시 호출하지 않아 미검증입니다.

[보존 스냅샷](snapshot.zip)은 당시 입력·평가기·설치 플러그인·최종 코드·상태를 담습니다. 실모델 시험 뒤의 안내 변경과 당시 시험 결과를 섞지 않습니다.

## 범위의 한계

작은 부분 완료 작업의 새 세션 연결과 산출물 성공입니다. 장기 실제 작업·컨텍스트 압축 후 재개·다른 Gemini 모델·경쟁 도구 비교는 남아 있습니다. 전역 설정을 상속한 공개 진단 사례 한 건으로 일반적인 모델 성능이나 하네스 우월성을 주장하지 않습니다.
