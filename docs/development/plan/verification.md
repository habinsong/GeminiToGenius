# 검증 계획

## 증거 수준

| 수준 | 검증 대상 | 의미 | 의미하지 않는 것 |
| --- | --- | --- | --- |
| L0 | 구조·문법·원문 목록 | 파일 존재, 올바른 형식, 기록 최신성 | 실행 성공 |
| L1 | 실제 로컬 프로세스·상태 테스트 | 종료 코드·시간 제한·복구·설치 동작 | Gemini 행동 품질 |
| L2 | 공식 계약의 이벤트 재생 | 알려진 입력의 파싱·출력·부작용 | 실제 호스트가 같은 이벤트를 발행함 |
| L3 | 제한된 실제 호스트 점검 | 실제 훅 탐지·스킬 호출·도구 결과 전달 | 다양한 작업에서의 일반적 품질 |
| L4 | 동일 조건 결과 평가 | 해당 작업집에서 성공률·비용·시간 비교 | 모든 환경에서 최고 |

## 필수 회귀 사례

- 설치 전 검증 실패, 설치 중 실패 복구, 사용자 파일 보존, 중복 설치, 공백·비ASCII 경로입니다.
- 규칙 원문 보존, 필수 훅 누락·중복·비활성·잘못된 시간 단위, 이동한 설치의 실패 감지와 재설치 복구입니다.
- 훅의 빈 입력·잘못된 JSON·빠진 필드·잘못된 타입·지원하지 않는 이벤트입니다.
- 중복 이벤트, 병렬 작업, 프로세스 중단 후 재개, 상태 파일 손상입니다.
- 실패한 검사·오래된 성공·검증 이후 변경·백그라운드 실행·완료 증거 없는 종료입니다.
- 사용자 취소·외부 오류·쿼터 제한·동일 실패 반복 시 강제 재개하지 않는지 확인합니다.
- 로그에 원본 프롬프트·환경 변수·인증 값·도구 출력 전체를 복제하지 않는지 확인합니다.
- 전체 목록에서 바이너리·개행·심볼릭 링크·추가·삭제·수정·민감 경로 제외를 검증합니다.

## 품질 비교

첫 비교는 같은 Gemini 모델·같은 작업·같은 쿼터 예산에서 기본 환경과 GTG를 비교합니다. Codex·Claude Code·OmO와 다른 모델을 사용한 결과는 제품 조합 비교로 별도 표시하고 하네스만의 개선이라고 해석하지 않습니다.

`python3 -m evals.harness prepare`는 모델 호출 없이 시험 폴더를 준비하고 `grade`는 폴더 밖의 고정 기준으로 산출물을 검사합니다. 함수 결과뿐 아니라 기존 호출자와 보호 파일을 확인하며, 수정 금지 요청은 별도 사람의 검토가 끝나기 전 전체 통과로 표시하지 않습니다. 진단 사례의 초기 오류·참조 수정·테스트 무력화·조기 정상 종료를 이용해 평가기 자체를 검사합니다.

새 기능 사례는 실제 Git 인덱스와 사용자 변경을 준비하고 CSV 기능·기존 JSON·파일명을 함께 확인합니다. 채점 중 소스 변경과 오래된 바이트코드로 인한 거짓 성공도 검사합니다. 준비된 프롬프트 해시와 준비·채점 환경을 기록하며 실제 호스트 관측과 구분합니다. [사례 및 한계](../../../evals/README.md).

작업집은 작은 버그, 여러 파일 기능, 회귀 테스트, 문서 조사, 실패 복구, UI 동선 등 실제 요청으로 구성합니다. 공개 과제와 보류 과제를 나누고 스킬 조정은 보류 과제에 직접 맞추지 않습니다. 성공률·미완료 오판·회귀·불필요한 변경·입력/출력 토큰·도구 횟수·총 소요 시간을 함께 기록합니다.

실모델 평가는 자동 대량 실행하지 않습니다. 먼저 L0~L2를 통과하고, L3에서만 짧은 작업 하나로 통합을 확인합니다. 사용 가능한 쿼터를 확인할 수 없다면 충분하다고 가정하지 않습니다. 실제 호출 비용과 토큰은 응답에 제공된 사용량만 기록하고 추정치는 구분합니다.

## UI

계획서에 특정 단어가 있다는 것으로 UI를 통과시키지 않습니다. 작업에 필요한 경로·로딩·빈 상태·오류·선택·키보드·포커스·좁은 화면·감속 설정을 실제 브라우저에서 확인합니다. 페이지 수·색·카드 사용은 제품 맥락에서 결정하며 일률적으로 강제하지 않습니다.
