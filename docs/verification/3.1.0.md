# 3.1.0 검증 범위

확인일: 2026-11-03. 이 문서는 하네스 코드와 지침의 오프라인 검증, 그리고 이번 변경의 근거가 된 조사 내역을 충실히 기록합니다. 실제 Gemini 4 Argon·Gemini 3.8 Flash 환경에서 이 지침이 환각이나 미완성 보고를 얼마나 줄여 주는지는 직접 측정하지 못했으며, Gemini 4 Carbon은 아직 일반 개발자에게 공개되지 않아 구체적 사양을 단정하지 않았습니다.

## 대상 모델에 대해 확인한 것

| 모델 | 확인한 내용 | 확인 방법 |
| --- | --- | --- |
| Gemini 4 Argon | 2026-09-30 발표, 2026-10-13 공개. 사고 수준은 LOW·MEDIUM·HIGH이고 기본값은 MEDIUM이며, Google 공식 문서는 여러 파일에 걸친 소프트웨어 작업에 HIGH를 권장합니다. temperature·top_p·top_k 같은 샘플링 값은 무시됩니다. | 검색 결과 요약문 대조 (네트워크 제한으로 원문 직접 열람 불가) |

벤치마크와 현장 사용자 보고는 서로 다른 양상을 보여 줍니다. Artificial Analysis 비교 페이지는 Terminal-Bench 4.0에서 Argon 57%, Carbon 65%, 3.8 Flash(High) 20%를 기록했다고 보고합니다. 반면 Argon의 지식 문답 환각률(AA-Omniscience)은 2차 출처에 따라 4%와 15%로 엇갈려 GTG 문서의 직접적인 근거로 채택하지는 않았습니다. 한 개발자는 Argon이 자신의 코드베이스 동작에 대해 주장의 절반 이상을 틀렸다고 보고했고, Gemini CLI 이슈에는 3.8 Flash가 금지 형식을 "모두 없앴습니다"라고 답한 바로 다음 줄에서 그 형식을 다시 쓴 사례와, Gemini가 사용자 스킬을 스스로 거의 열지 않는다는 보고가 있었습니다. 모두 통제된 측정이 아닌 개별 보고이므로, GTG는 이를 확정된 사실의 증거가 아니라 설계 방향을 가다듬는 참고 근거로만 활용했습니다.

## 구현과 직접 실패 경로

| 보호 | 확인 방법 |
| --- | --- |
| 미완성 코드 | 새로 작성한 줄의 TODO·FIXME와 `추후 구현` 같은 주석, 본문이 pass·...·NotImplementedError뿐인 함수를 차단합니다. 기존에 있던 TODO, 소문자 todo 변수, HTML `placeholder` 속성은 잡지 않으며, `@abstractmethod`나 실제 하위 클래스가 구현하는 기반 메서드도 막지 않습니다. |
| 대형 파일·클래스 누적 | 400줄을 초과하며 커진 파일과 메서드가 20개를 넘어 늘어난 클래스를 차단합니다. 이미 큰 파일의 기존 줄을 수정하는 것은 허용하되 새 최상위 정의를 추가하면 차단하며, 시험 파일은 검토 항목으로만 남깁니다. |
| 불필요한 추상화 | 구현이 하나뿐인 추상 클래스, 모든 메서드가 단순 전달뿐인 래퍼 클래스, 인자를 그대로 넘기는 함수, 호출하는 곳이 없는 새 정의를 검토 항목으로 알리고 호출 코드가 생기면 신호가 해제되는지도 확인합니다. |
| 기준 고정 | 작업 중간에 커밋하면 기본 기준(HEAD)이 이동하므로 시작 커밋을 `--base`로 고정하여 작업 전체를 다시 검토하는지 확인합니다. 잘못된 리비전이나 `-`로 시작하는 리비전, 작업공간 외부 및 `.git` 경로는 거부합니다. |
| 문체 상투구 | 한국어 6종과 영어 5종의 차단 규칙마다 걸려야 하는 문장과, 유사하지만 걸리면 안 되는 문장(문장 중간의 `결론적으로`, `무결성`, `되어 있는` 등)을 함께 시험합니다. 코드 블록, 인라인 코드, URL, 머리말은 검사하지 않습니다. |
| 문체 리듬 | 동일한 어미 다섯 번 연속, 짧은 문장 네 개 연속, 길이가 지나치게 고르고 긴 문장이 없는 문서를 검토 항목으로 알리고 목록과 제목은 리듬 측정에서 제외합니다. 읽지 못한 문서가 하나라도 있으면 통과로 인정하지 않습니다. |
| 배포 문서 자체 | 모델이 읽는 규칙과 스킬 전체, 대표 안내문에 차단 상투구가 없는지 시험합니다. 지침 스스로가 금지한 표현을 사용하지 않도록 방지하기 위함입니다. |
| 교훈 기록 | 근거가 없거나 작업공간 외부, 링크, 없는 파일을 가리키는 교훈이나 눈에 보이지 않는 유니코드가 섞인 교훈을 거부합니다. 같은 문장은 한 번만 저장하고 100개를 초과하면 오래된 기록부터 정리하며, 깨진 줄과 파일은 건너뛰어 훅을 중단시키지 않습니다. |
| 턴 시작 안내 | 실제로 패키지를 빌드해 Antigravity·Gemini CLI 훅 프로세스를 실행했을 때 설치된 `run.py` 경로가 안내에 실리는지, 저장소 원본에서는 경로를 임의로 꾸며내지 않는지 확인합니다. 교훈은 첫 호출에만 포함됩니다. |

시험이 실질적인 결함을 온전히 잡아내는지 확인하기 위해 구현을 의도적으로 훼손하는 변이 시험을 진행했습니다. 구조 검사 8개, 문체 검사 7개, 턴 안내 3개, 런타임 1개 변이 가운데 초기에 탐지되지 않은 항목은 3개였습니다. 하위 클래스가 있는 기반 클래스의 `NotImplementedError` 예외를 지운 변이는 시험이 `@abstractmethod` 경우만 다루어 누락되었고, 복잡도 검토 신호를 끈 변이는 해당 신호를 직접 검사하는 시험 사례가 없어 누락되었으므로 두 경우 모두 검증 사례를 보강하여 현재는 확실히 잡아냅니다. 나머지 하나는 교훈을 매 호출마다 읽도록 변경한 변이로서 첫 호출이 아니면 안내 문구가 나가지 않아 출력이 동일한 동등 변이였습니다.

## 자체 검사에서 드러난 점

이번 변경 전체에 대해 `structure`와 `prose`를 직접 실행해 보니, 처음에는 시험 픽스처의 문자열 `"# TODO"`와 정규식 정의 줄까지 주석 표식으로 인식되어 차단이 9건 발생했습니다. 이에 Python 파일은 `tokenize`로 실제 주석만 선별하도록 수정하고 문자열 속 표식을 제외하는 시험을 추가했으나, 그 후에도 표식 규칙을 설명하던 주석 한 줄이 대문자 표식 단어를 그대로 사용하여 걸렸습니다. 검사기의 판단이 타당하다고 보아 주석 표현을 수정했습니다. 다른 언어는 주석 기호 뒤의 표식을 정규식으로 탐색하므로 문자열 속 오탐이 일부 남을 수 있습니다.

함수 복잡도 검토 기준도 초기에는 15로 설정했었는데, 이 기준에서는 불리언 조건 몇 개를 조합한 20~30줄 분량의 단순 정책 함수까지 대부분 걸려 신호가 소음이 되었습니다. 작성한 코드가 걸렸다는 이유로 기준을 임의 완화하는 것은 하네스가 금지하는 시험 왜곡과 동일하므로, radon 공식 문서의 등급 경계(C 11–20, D 21–30)를 검토한 뒤 D 등급부터 알리도록 합리적으로 조정했고 그보다 복잡했던 내부 함수 두 개(`changes.select`, `code_shape.class_info`)는 실제로 분리하여 복잡도를 낮췄습니다. 이 기준은 차단이 아닌 검토 신호에만 적용됩니다.

코드를 재검토하는 과정에서 성능 병목도 하나 발견했습니다. 초기 구현은 새 최상위 정의가 나타날 때마다 작업공간 내 Python 본문 전체를 정규식으로 다시 탐색하여, 대형 저장소에 정의가 많이 늘어나면 검사 제한 시간을 초과할 위험이 있었습니다. 식별자와 상속 목록을 단 한 번만 집계하는 색인 구조로 개선한 뒤, Python 파일 2,000개(디스크 16MB) 규모의 합성 저장소에서 새 정의 200개를 추가한 변경을 0.59초 만에 검사 완료했습니다.

최종 자체 검사 결과는 차단 0건, 검토 3건으로 정리되었습니다. `__main__.build_parser`는 CLI 계약을 한곳에 선언하는 82줄 분량의 평면 함수(복잡도 4)이고, `hooks.handle`은 변경 전부터 복잡도 29였던 함수에 실행기 경로 조건식 하나가 추가된 상태이며, `tests/test_runtime.py`의 시험 클래스는 본래 메서드 23개였고 이번 작업에서 늘어나지 않았습니다. 핵심 실행 경로인 `hooks.handle`의 전면 재구성은 이번 작업 범위에 포함하지 않았습니다. 문서 영역의 자체 검사는 차단 0건이며 검토 항목은 이번에 수정하지 않은 `code-intake.md`의 문장 길이 하나뿐이었습니다.

## 확인 명령

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests
python3 scripts/catalog.py --check
```

Linux 컨테이너(Python 3.13, root) 환경에서 전체 시험 411개를 2회 반복 실행했고 모두 정상 통과했습니다(111초, 116초). 작업 전 기준선은 363개 중 1개 오류였는데 root 권한에서 PID 1에 신호를 보낼 수 있어 "다른 사용자 PID" 전제가 깨지는 런타임 시험이었습니다. 이 시험은 권한 거부 상황을 명시적으로 재현하도록 수정했고 권한 거부를 정상 프로세스로 오인하는 변이를 적용하면 여전히 실패하도록 엄격히 검증했습니다.

## 남은 한계

실제 Gemini 환경에서 지침 채택률, 환각 감소, 미완성 보고 감소, 교훈 기록의 실질적 효과는 정량 측정하지 못했습니다. 구조 검사는 Python만 AST로 정밀 분석하고 다른 언어는 줄 수와 주석 표식만 확인하므로 문자열로 동적 조합한 호출은 참조로 잡지 못합니다. 문체 검사는 표현 목록과 문장 길이로 신호를 찾을 뿐 글의 전반적인 품질이나 사실 여부를 판단하지 않으며 개인 문체가 독특한 사람 글을 검토 신호로 잡을 수도 있습니다. Windows 환경 설치와 데스크톱 Antigravity의 실제 도구 이름도 직접 확인하지 못했습니다.
