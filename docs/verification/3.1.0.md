# 3.1.0 검증 범위

확인일: 2026-11-03. 이 문서는 하네스 코드와 지침의 오프라인 검증, 그리고 이번 변경의 근거가 된 조사를 기록합니다. 실제 Gemini 4 Argon·Gemini 3.8 Flash에서 이 지침이 환각이나 미완성 보고를 줄이는지는 측정하지 않았고, Gemini 4 Carbon은 아직 일반 개발자에게 공개되지 않아 사양을 가정하지 않았습니다.

## 대상 모델에 대해 확인한 것

| 모델 | 확인한 내용 | 확인 방법 |
| --- | --- | --- |
| Gemini 4 Argon | 2026-09-30 발표, 2026-10-13 공개. 사고 수준은 LOW·MEDIUM·HIGH이고 기본값은 MEDIUM이며, Google 문서는 여러 파일에 걸친 소프트웨어 작업에 HIGH를 권합니다. temperature·top_p·top_k 같은 샘플링 값은 무시됩니다. | 검색 결과 요약. 원문은 아래 네트워크 제한으로 열지 못함 |
| Gemini 3.8 Flash | 2026-09-02 공개, 모델 ID `gemini-3.8-flash`. 사고 수준은 low·medium·high이고 기본값은 medium, minimal은 오류입니다. 노력 수준이 높을수록 토큰을 더 쓸 수 있다고 안내합니다. | 검색 결과 요약 |
| Gemini 4 Carbon | 2026-10-28 발표. 사이버 방어 협력사(Fairwind 프로그램)에 먼저 제공하며 일반 공개 날짜는 없습니다. | 검색 결과 요약 |

벤치마크와 현장 보고는 서로 다른 그림을 보여 줍니다. Artificial Analysis 비교 페이지는 Terminal-Bench 4.0에서 Argon 57%, Carbon 65%, 3.8 Flash(High) 20%를 보고합니다. 반면 Argon의 지식 문답 환각률(AA-Omniscience)은 2차 출처에 따라 4%와 15%로 엇갈려서 GTG 문서의 근거로 쓰지 않았습니다. 한 개발자는 Argon이 자기 코드베이스의 동작에 대해 주장의 절반 넘게 틀렸다고 보고했고, Gemini CLI 이슈에는 3.8 Flash가 금지 형식을 "모두 없앴다"고 답한 바로 다음 줄에서 그 형식을 다시 쓴 사례와, Gemini가 사용자 스킬을 스스로 거의 열지 않는다는 보고가 있습니다. 모두 통제된 측정이 아닌 개별 보고이므로, GTG는 이를 사실의 증명이 아니라 설계 방향의 근거로만 썼습니다.

## 구현과 직접 실패 경로

| 보호 | 확인 방법 |
| --- | --- |
| 미완성 코드 | 새로 넣은 줄의 TODO·FIXME와 `추후 구현` 같은 주석, 본문이 pass·...·NotImplementedError뿐인 함수를 차단합니다. 이미 있던 TODO, 소문자 todo 변수, HTML `placeholder` 속성은 잡지 않고, `@abstractmethod`나 실제 하위 클래스가 구현하는 기반 메서드도 막지 않습니다. |
| 대형 파일·클래스 누적 | 400줄을 넘기며 커진 파일과 메서드가 20개를 넘어 늘어난 클래스를 차단합니다. 이미 큰 파일의 기존 줄을 고치는 것은 막지 않고 새 최상위 정의를 더하면 막으며, 시험 파일은 검토로만 남깁니다. |
| 헛 추상화 | 구현이 하나인 추상 클래스, 모든 메서드가 전달뿐인 래퍼 클래스, 인자를 그대로 넘기는 함수, 부르는 곳이 없는 새 정의를 검토 신호로 알리고, 부르는 코드가 생기면 신호가 사라지는지도 확인합니다. |
| 기준 고정 | 작업 중간에 커밋하면 기본 기준(HEAD)이 움직이고, 시작 커밋을 `--base`로 고정하면 작업 전체를 다시 보는지 확인합니다. 잘못된 리비전, `-`로 시작하는 리비전, 작업공간 밖·`.git` 경로는 거부합니다. |
| 문체 상투구 | 한국어 6종·영어 5종의 차단 규칙마다 걸려야 하는 문장과, 비슷하지만 걸리면 안 되는 문장(문장 중간의 `결론적으로`, `무결성`, `되어 있는` 등)을 함께 시험합니다. 코드 블록·인라인 코드·URL·머리말은 보지 않습니다. |
| 문체 리듬 | 같은 어미 다섯 번 연속, 짧은 문장 네 개 연속, 길이가 고르고 긴 문장이 없는 문서를 검토 신호로 알리고, 목록과 제목은 리듬 측정에서 뺍니다. 읽지 못한 문서가 하나라도 있으면 통과로 보지 않습니다. |
| 배포 문서 자체 | 모델이 읽는 규칙·스킬 전부와 대표 안내문에 차단 상투구가 없는지 시험합니다. 지침이 스스로 금지한 표현을 쓰지 않게 하려는 것입니다. |
| 교훈 기록 | 근거가 없거나 작업공간 밖·링크·없는 파일을 가리키는 교훈, 보이지 않는 문자가 섞인 교훈을 거부합니다. 같은 문장은 한 번만 저장하고 100개를 넘으면 오래된 것부터 지우며, 깨진 줄과 깨진 파일은 건너뛰어 훅을 멈추지 않습니다. |
| 턴 시작 안내 | 실제로 패키지를 빌드해 Antigravity·Gemini CLI 훅 프로세스를 돌렸을 때 설치된 `run.py` 경로가 안내에 실리는지, 저장소 원본에서는 경로를 지어내지 않는지 확인합니다. 교훈은 첫 호출에만 붙습니다. |

시험이 정말 결함을 잡는지 보려고 구현을 일부러 망가뜨리는 변이 시험도 했는데, 구조 검사 8개와 문체 검사 7개, 턴 안내 3개, 런타임 1개 변이 가운데 처음에 살아남은 것은 셋이었습니다. 하위 클래스가 있는 기반 클래스의 `NotImplementedError` 예외를 지운 변이는 시험이 `@abstractmethod` 경우만 다뤄서 놓쳤고, 복잡도 검토 신호를 끈 변이는 그 신호를 직접 시험하는 사례가 없어서 놓쳤기 때문에 두 경우 모두 사례를 더해 지금은 잡습니다. 나머지 하나는 교훈을 모든 호출에서 읽게 바꾼 변이로, 첫 호출이 아니면 안내 문구가 나가지 않으니 출력이 같은 동등 변이입니다.

## 자기 검사에서 드러난 것

이번 변경 전체에 `structure`와 `prose`를 직접 돌려 보니, 처음에는 시험 픽스처의 문자열 `"# TODO"`와 정규식 정의 줄까지 주석 속 표식으로 잡혀 차단이 9건 나왔습니다. 그래서 Python 파일은 `tokenize`로 진짜 주석만 보도록 고치고 문자열 속 표식을 잡지 않는 시험을 더했는데, 그 뒤에도 표식 규칙을 설명하던 제 주석 한 줄이 대문자 표식 단어를 그대로 써서 걸렸습니다. 검사기의 판단이 맞다고 보고 주석 표현을 바꿨습니다. 다른 언어는 여전히 주석 기호 뒤의 표식을 정규식으로 찾으므로 문자열 속 오탐이 남을 수 있습니다.

함수 복잡도 검토 기준도 처음에는 15였는데, 이 기준에서는 불리언 조건 몇 개를 묶은 20~30줄짜리 정책 함수까지 대부분 걸려 신호가 소음이 됐습니다. 제 코드가 걸렸다고 기준을 푸는 것은 이 하네스가 금지하는 시험 완화와 모양이 같으므로, 기준은 radon 공식 문서의 등급 경계(C 11–20, D 21–30)를 확인한 뒤 등급 D부터 알리도록 바꿨고, 그보다 복잡했던 제 함수 두 개(`changes.select`, `code_shape.class_info`)는 실제로 나눠서 낮췄습니다. 이 기준은 차단이 아니라 검토 신호에만 쓰입니다.

코드를 다시 읽다가 성능 문제도 하나 찾았습니다. 처음 구현은 새 최상위 정의마다 작업공간의 Python 본문 전체를 정규식으로 다시 훑어서, 큰 저장소에 정의를 많이 더하면 검사 시간 제한을 넘길 수 있었습니다. 식별자와 상속 목록을 한 번만 세는 색인으로 바꾼 뒤, Python 파일 2,000개(디스크 16MB)짜리 합성 저장소에서 새 정의 200개를 더한 변경을 0.59초에 검사했습니다.

최종 자기 검사는 차단 0건, 검토 3건입니다. `__main__.build_parser`는 CLI 계약을 한곳에 선언하는 82줄짜리 평면 함수(복잡도 4)이고, `hooks.handle`은 변경 전부터 복잡도 29였던 함수에 실행기 경로 조건식 하나가 더해진 것이며, `tests/test_runtime.py`의 시험 클래스는 원래 메서드 23개였고 이번에 늘지 않았습니다. 핵심 경로인 `hooks.handle`의 재구성은 이번 범위에서 하지 않았습니다. 문서 쪽 자기 검사는 차단 0건이고, 검토 신호는 이번에 고치지 않은 `code-intake.md`의 문장 길이 하나입니다.

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests
python3 scripts/catalog.py --check
```

실제 Gemini에서 지침 채택률, 환각 감소, 미완성 보고 감소, 교훈 기록의 효과는 측정하지 않았습니다. 구조 검사는 Python만 AST로 보고 다른 언어는 줄 수와 주석 표식만 보며, 문자열로 조합한 동적 호출은 참조로 잡지 못합니다. 문체 검사는 표현 목록과 문장 길이로 신호를 찾을 뿐 글의 품질이나 사실 여부를 판정하지 않고, 개인 문체가 강한 사람 글을 검토 신호로 잡을 수 있습니다. Windows 설치와 데스크톱 Antigravity의 실제 도구 이름도 확인하지 않았습니다.
