# 3.0.1 검증 범위

확인일: 2026-10-16. 이 문서는 하네스 구현과 패키지, 설치의 무결성 검증을 실제 모델 품질과 엄격히 구분하여 기록합니다. 3.0.0의 모델 비교 결과를 새 규칙의 개선 효과로 재사용하지는 않습니다.

## 구현과 직접 실패 경로

| 보호 | 확인 방법 |
| --- | --- |
| 빌드와 필수 시험 | 실제 컴파일 실패 시 시험 실행을 차단하고, 문법이 정상이더라도 없는 API나 필드, 함수 참조는 실제 호출 단계에서 실패시킵니다. 정상 수정 후 PRD 세 시험과 증명서 재현을 확인합니다. |
| 오래된 성공 | 제품 입력이나 PRD가 변경되거나 빌드를 다시 실행한 뒤에는 이전 시험 성공 기록을 무효화합니다. |
| 필수 시험 누락 | 다른 시험이 통과하더라도 필수 시험 ID가 실제 성공 목록에 없거나 skip/expectedFailure로 끝나면 실패 처리합니다. 조기 종료와 오래된 캐시도 함께 대조합니다. |
| 환경과 비교 | 현재 실행기와 채점 조건, 시간 제한이 없거나 다르면 비교를 차단합니다. 조건 일치를 원격 모델이나 자원 집행, 실사용 적합성으로 확대 해석하지 않습니다. |
| 비판적 판단 | 허위 API, 중간 거짓 주장, 과장, 무조건적 긍정, 불가능한 제안, 환경 차이, 범위 확대, 메모, 정보 부족을 위한 사람 검토 사례를 제공합니다. 타당한 제안의 선별적 채택도 포함하며, 의미적 판단을 자동으로 통과시키지 않습니다. |
| 증명서 재실행 | 검사 도중 입력을 복구하여 원래 지문으로 되돌리더라도 실패 처리합니다. POSIX 프로세스 그룹의 백그라운드 자식 프로세스와 타임아웃 잔여 실행을 정리합니다. |
| 설치 경계 | 별도 홈 설치에서 실제 호스트 등록이 호출되지 않음을 확인합니다. 실제 CLI 등록 실패와 다른 호스트용 패키지는 정상 설치로 보고하지 않습니다. 실제 CLI의 공용 경로 복사도 기존 패키지를 보존한 후 호스트에 맞게 복구합니다. |

공개 회귀 시험은 `tests/test_code_contract.py`, `test_required_unittest.py`, `test_build_scenario.py`, `test_release_regressions.py`에 마련되어 있습니다. 의도적으로 잘못된 코드를 넣은 평가 fixture는 실패 입력을 검증하기 위한 데이터이며 배포용 실행 코어가 아닙니다.

## 확인 명령

macOS 로컬 전체 회귀 363개가 111.362초 만에 모두 통과했습니다. 실제 제품, 평가, 스크립트, 시험 Python 모듈 79개의 컴파일도 정상 통과했습니다. 의도적으로 깨뜨린 평가 fixture는 이 모듈 집계와 구분하여 독립 실패 사례로 검사합니다. 셸 문법과 diff 공백, 변경 문서 링크도 확인했습니다.

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests
bash -n scripts/install.sh
python3 scripts/catalog.py --check
```

설치 검사는 실제 사용자 홈 디렉터리를 수정하기 전에 별도의 임시 홈 경로에서 설치, doctor, 제거, 보존 경로를 면밀히 확인합니다. 공식 패키지 구조와 훅 진입점은 세 호스트에 대해 검증합니다. 실제 호스트의 목록과 검증기 성공 기록도 모델이 새 스킬을 채택했다는 증거와는 엄격히 구분합니다.

실제 macOS 설치 환경에서도 구버전 활성 경로 세 곳을 제거하고 3.0.1 패키지로 안전하게 교체했습니다. 구버전은 복구본으로 보존하며 다른 플러그인 등록 상태는 온전히 유지했습니다. `agy 1.1.28`의 검증기는 스킬 3개와 훅 2개를 정상 처리했습니다.

실제 CLI의 PRD·빌드·API 합성 사례 한 건은 48.767초 후 종료 코드 0과 `SUCCESS`를 반환했으나 `RunCommand`가 권한 부족으로 거부되었습니다. 파일 변경이나 제품 실행은 없었고 독립 컴파일 및 기능 채점은 실패했습니다. 이 시행 결과는 실제 작업 성공이나 모델 품질 개선의 증거가 아닙니다. 임의의 권한 우회나 전역 허용 설정 변경, 추가 모델 재시도는 진행하지 않았습니다.

## 호환성과 한계

실행 코어와 코드 작업 계약은 특정 모델이나 언어 이름에 독립적으로 동작합니다. 프로젝트의 실제 빌드, 타입 검사, 시험 명령을 직접 연결해야 하며 내장 시험 ID 관측은 Python unittest만 지원합니다. PRD 전체의 의미나 누락된 빌드 입력, 시험 설계 자체의 타당성을 스스로 판단하지는 않습니다.

실제 Gemini의 환각 감소나 지침 채택률, 컴파일 성공률 향상 여부는 이번 릴리즈에서 정량 측정하지 않았습니다. OS 샌드박스, 악성 시험의 관측 위조 방어, Windows 환경 설치, 네트워크 파일 잠금, 모든 언어의 실행 관측, 장기 작업 안정성과 실제 기기 적합성도 보장하지는 않습니다.
