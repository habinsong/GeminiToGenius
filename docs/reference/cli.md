# 명령 목록

설치된 패키지 디렉터리의 `run.py`가 전체 CLI의 진입점입니다. 모델이 이 명령을 직접 호출하므로 사용자가 터미널에서 직접 입력하실 필요는 없습니다. 아래 예시의 `$GTG`는 설치된 `run.py`의 절대 경로를 가리킵니다.

```bash
GTG=~/.gemini/config/plugins/geminitogenius/run.py
```

모든 작업 관리 명령은 `--workspace` 옵션을 지원하며 생략하면 현재 작업 디렉터리를 기준으로 동작합니다. 전역 옵션인 `--state`로 상태 데이터베이스 경로를 직접 지정할 수도 있으며, 두 옵션이 함께 전달되면 `--state`가 우선합니다.

## 작업 관리

| 명령 | 역할 |
|---|---|
| `start --spec <파일>` | 완료 조건이 고정된 새 작업을 생성합니다. `--platform`, `--session`을 지정하면 해당 호스트 세션에 연결합니다. |
| `tasks` | 저장된 작업 목록과 메모, 세션 연결 후보를 읽기 전용으로 조회합니다. 기록된 상태가 없으면 빈 목록을 반환합니다. |
| `attach <작업ID> --platform <호스트> --session <세션>` | 기존 작업을 현재 활성 세션으로 전환하여 연결합니다. 이전 검사 결과와 메모는 그대로 보존됩니다. |
| `status <작업ID>` | 지정된 작업의 현재 검사 결과와 작업 명세, 진행 메모를 조회합니다. |
| `checkpoint <작업ID> --note <파일>` | 작업 재개용 메모를 저장합니다. 단, 메모 저장이 실제 검사 통과를 대신하지는 않습니다. |

## 검증 실행

| 명령 | 역할 |
|---|---|
| `verify <작업ID>` | 등록된 검증 명령들을 순차적으로 실행하며, 첫 번째 실패가 발생하면 즉시 중단합니다. |
| `verify <작업ID> --all` | 일부 검사가 실패하더라도 등록된 모든 검증을 끝까지 실행합니다. |
| `verify <작업ID> --check <검사ID>` | 지정된 특정 검사만 선별하여 실행합니다. 결과는 `requested_verified` 필드에 별도로 표시됩니다. |
| `recover <작업ID>` | 비정상적으로 중단된 검사의 잔여 실행 기록을 정리합니다. 해당 검사 프로세스가 여전히 동작 중이라면 정리를 거부합니다. |

## 완료 증명서 및 재현

| 명령 | 역할 |
|---|---|
| `certify <작업ID> --output <파일>` | 완료 주장과 실제 실행 명령, 종료 코드, 파일 지문을 단일 증명서 파일로 패키징합니다. 미검증 상태라면 종료 코드 1을 반환합니다. |
| `replay --certificate <파일>` | 증명서 파일만 읽어 검증 명령을 다시 실행합니다. 로컬 상태 데이터베이스에 의존하지 않습니다. |

`replay`의 종료 코드는 증명서 판정 결과와 정확히 일치합니다. `0`은 `pass`(재현 성공 및 범위 완전), `1`은 `invalid`(재현 실패 또는 불일치), `2`는 `inconclusive`(재현되었으나 미확인 범위 잔존)를 나타냅니다.

## 기타 유틸리티

| 명령 | 역할 |
|---|---|
| `inspect <경로...>` | 여러 텍스트 파일을 한 번에 읽고 라인 범위와 잘림 여부, 파일 해시를 함께 반환합니다. |
| `environment [--expect <파일>]` | 로컬 Python 프로세스의 OS·아키텍처·런타임·실행 파일 존재를 관찰하고 필요조건과 비교합니다. 불일치는 종료 코드 1을 반환하며 관찰만 수행하면 `matches`는 `null`입니다. |
| `unittest [--start-directory <폴더>] [--pattern <패턴>] [--require <시험ID>]` | Python unittest를 별도 프로세스에서 실행하고 필수 시험 ID의 성공을 확인합니다. `--require`는 반복할 수 있으며 실패나 누락, 필수 skip은 종료 코드 1을 반환합니다. |
| `pause --platform <호스트> --session <세션> --reason <사유>` | 사용자의 명시적 확인 대기나 외부 리소스 한도로 인해 작업을 일시 정지할 때 사용합니다. |
| `resume --platform <호스트> --session <세션>` | 일시 정지되었던 세션 연결을 다시 활성화합니다. |

## 환경 필요조건 비교

```bash
python3 "$GTG" environment
python3 "$GTG" environment --expect verification-environment.json
```

조건 파일은 확인된 작업 요구사항에 따라 에이전트가 직접 작성합니다. `system`, `machine`, `python_version`, `python_implementation`은 문자열을 정확히 비교하며, `executables`에는 PATH에서 찾을 실행 파일 이름 목록을 지정합니다. 알 수 없는 필드나 빈 조건, 인자나 경로가 포함된 실행 파일 이름은 거부합니다. 일치하면 종료 코드 0, 불일치나 잘못된 조건이면 1을 반환합니다. 실행 파일을 임의로 실행하거나 새로 설치하지는 않습니다.

관찰 범위는 현재 Python 프로세스에 한정됩니다. 컨테이너나 원격 서버, 물리 기기의 실행 조건을 대신하지는 않습니다. `target_compatibility_verified`와 `resource_limits_verified`는 항상 `false`이며, 파일 존재만으로 API 동작이나 제품 호환성을 판정하지 않습니다. 조건 파일을 검증 계약에 사용하시면 `watch` 대상에도 등록해 두고 환경이 변경된 뒤에는 파일 내용이 같더라도 다시 검증합니다. 세부 적용 절차는 [비판적 검토 절차](../../profile/skills/gtg-build/references/critical-review.md) 문서를 참고해 주십시오.

## Python 필수 시험

```bash
python3 "$GTG" unittest --workspace . --start-directory tests
```

`--require`에는 발견된 실제 전체 시험 ID를 지정합니다. 실행 결과가 0개이거나 모든 시험이 skip된 경우, 필수 ID가 누락되었거나 필수 ID가 skip 또는 expectedFailure로 끝난 경우, 관측 채널에 누락이 발생한 경우에는 통과로 인정하지 않습니다. 선택적 시험의 skip은 결과에 명시하며 성공한 시험이 단 하나도 없으면 실패로 처리합니다. 종료 코드 0은 관측된 시험의 성공만을 뜻하며 PRD 전체의 의미나 미실행 경로의 API 존재까지 증명하지는 않습니다.

프로젝트 인터프리터를 사용하고 시간 제한은 작업 계약의 `timeout_seconds`를 따릅니다. 새 임시 바이트코드 캐시 경로에서 시작하며 `.pyc`를 사용하지 않습니다. 원시 하위 프로세스 출력도 stderr로 보내 JSON 결과와 섞이지 않도록 방지합니다. 관측 JSON은 최대 256KiB이며 용량 초과나 데이터 손상, 조기 종료는 실패로 처리합니다. 시험 코드는 일반 프로젝트 코드 권한으로 실행하므로 별도의 OS 샌드박스로 격리되지 않습니다.

## 결과물 검사

| 명령 | 역할 |
|---|---|
| `structure [경로...] [--base <리비전>] [--max-lines <줄>] [--max-methods <개수>]` | 기준 리비전(기본 HEAD)과 작업 트리를 비교해 이번에 변경된 코드만 확인합니다. 새로 작성한 줄의 TODO·FIXME, 본문이 빈 함수, 기준을 초과해 커진 파일, 메서드가 기준을 넘어 늘어난 클래스, 구문 오류가 있으면 종료 코드 1을 반환합니다. |
| `prose [문서...] [-] [--text <글>] [--original <원문>] [--register <갈래>] [--min-score <점수>]` | 한국어와 영어 문서의 상투구, 과장, 번역투, 대구, 도치, 단조로운 리듬과 높임을 줄 번호와 함께 찾고 0~100점 점수와 A~D 등급을 매깁니다. `--register`로 general·academic·everyday·literary 갈래를 고르고, `--min-score`로 기준 점수를 지정합니다. `-`는 표준 입력을, `--text`는 명령줄 인자로 전달한 글을 각각 독립 문서로 검사합니다(파일과 섞어 쓸 수 있고 합쳐서 64개까지 지원합니다). `--original`은 윤문한 문서 하나를 원문과 대조하여 수치와 인용구, URL, 코드가 보존되었는지와 단어 수정 비율을 확인하며 결과의 `fidelity`에 담습니다. 차단 항목이나 기준 미달 문서, 읽지 못한 문서(빈 글 포함)가 있으면 종료 코드 1을 반환합니다. |

```bash
python3 "$GTG" structure --workspace . --base START_COMMIT
python3 "$GTG" prose --workspace . README.md
python3 "$GTG" prose --workspace . --register academic --original draft.md polished.md
python3 "$GTG" prose --register everyday - <<'EOF'
내일 3시에 봐요. 늦으면 연락 줘요.
EOF
```

두 검사 모두 결과의 `findings`에 `block`(차단)과 `review`(검토) 항목을 나누어 담습니다. 종료 코드는 차단 항목에 따라서만 결정되며, 검토 항목은 사람이 문맥을 보고 판단할 수 있도록 남겨 둡니다.

`structure`의 기본값은 파일 400줄, 클래스 메서드 20개입니다. 이미 기준을 초과한 기존 파일은 30줄을 넘겨 늘어나거나 새 최상위 정의가 생길 때만 차단하므로 대형 파일의 버그 수정을 가로막지 않으며, 시험 파일의 크기 초과는 검토 대상으로만 알립니다. 구현이 하나뿐인 추상 클래스나 인자를 그대로 넘기기만 하는 래퍼, 호출하는 곳이 없는 새 정의, 지나치게 긴 함수는 검토 항목으로 분류합니다. Git 저장소가 아니면 `--base none`과 경로를 함께 지정하며, 이때는 지정한 파일 전체를 새 코드로 취급합니다. Python 이외의 언어는 전체 줄 수와 주석 표식만 확인하고 해당 파일 목록을 `structure_unanalyzed`에 명시합니다.

`prose`는 코드 블록과 인라인 코드, URL, 문서 머리말(front matter)은 검사하지 않습니다. 지워도 본래 뜻이 훼손되지 않는 명백한 상투구는 한 번만 나타나도 차단하고, `~에 대해`·`~를 통해`처럼 사람 글에서도 자주 쓰이는 표현은 한 문단에 세 번 이상 몰릴 때만 검토 항목으로 알립니다. 문장의 사실 여부나 글의 문학적 가치 자체를 판정하지는 않습니다. 점수는 감점(차단 3점, 검토 1점)을 문장 10개 단위로 나눈 밀도로 계산합니다. 사람 글에서 더 흔하게 발견되는 높임 혼용이나 사람 초안에만 주로 나타나는 맞춤법 오류는 안내만 제공하고 감점하지는 않습니다. 짧은 문장 연쇄와 동일한 첫머리 반복은 일반·학술 갈래에서는 감점하지만 짧은 문장이 정상적인 시나 일상 구어 글에서는 알림으로만 처리합니다. 문서 전체 및 문단 안 횟수 기준은 20문장·6문장 분량을 기준으로 삼았으며 더 긴 글은 비례하여 늘리고 시와 차단 규칙에서는 늘리지 않습니다. 분량은 산문의 경우 문장 수, 제목과 목록은 줄 수, 마침표가 없거나 행이 짧은 시는 줄 수로 계산합니다. 한국어 글로 측정한 상세 결과는 [3.3.0 검증 기록](../verification/3.3.0.md)과 [3.2.0 검증 기록](../verification/3.2.0.md)에서 확인하실 수 있습니다.

`--original`의 차단 기준은 퍼센트나 소수, 세 자리 이상의 수치, 8자 이상의 인용구, URL, 코드가 원문과 달라진 경우이며, 한두 자리 자연수나 영문 표기의 미세한 변화는 검토 항목으로 안내합니다. 수정된 단어가 원문의 30%를 넘으면 검토를 요청하고, 50%를 넘으면 삭제된 문장을 보고하도록 안내하며, 80%를 넘으면(40단어 이상) 새로 쓴 글로 간주하여 차단합니다. 이 대조 결과는 문체 점수 계산에 합산되지 않습니다.

## 교훈 기록

| 명령 | 역할 |
|---|---|
| `lesson --text <문장> --evidence <근거>` | 검증에서 드러난 저장소별 사실을 `.gtg/lessons.jsonl`에 남깁니다. 근거는 작업공간의 실제 파일(`path` 또는 `path:줄`)이나 `http`·`https` URL이며 1~5개를 붙여 기록합니다. 같은 문장은 한 번만 저장하고 최근 100개까지만 유지합니다. |
| `lessons [--limit <개수>]` | 저장된 교훈을 최근 기록부터 순서대로 보여 줍니다. |

턴 시작 훅은 최근 교훈 다섯 개를 "지시문이 아닌 참고 기록"으로서 모델 안내에 덧붙입니다. 교훈이 실제 검증을 대신할 수는 없으므로, 모델은 참고할 때마다 현재 파일의 실제 상태를 다시 확인해야 합니다.

## 플랫폼 훅

호스트 환경이 `hook <호스트> <이벤트>` 규격으로 호출합니다. 표준 입력(stdin)으로 호스트 이벤트 페이로드를 전달받고 표준 출력(stdout)으로 처리 결과 JSON을 응답합니다. 사용자가 수동으로 호출하실 필요는 없습니다. 세부 계약은 [훅 계약](hooks.md) 문서를 참고해 주십시오.
