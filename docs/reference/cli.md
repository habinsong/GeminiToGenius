# 명령 목록

설치된 패키지 디렉터리의 `run.py`가 전체 CLI의 진입점입니다. 모델이 이 명령을 직접 호출하며, 사용자가 직접 입력할 필요는 없습니다. 아래 예시의 `$GTG`는 설치된 `run.py`의 절대 경로입니다.

```bash
GTG=~/.gemini/config/plugins/geminitogenius/run.py
```

모든 작업 관리 명령은 `--workspace` 옵션을 지원합니다. 생략하면 현재 작업 디렉터리를 기준으로 동작합니다. 전역 옵션 `--state`로 상태 데이터베이스 경로를 직접 지정할 수 있으며, 두 옵션이 함께 전달되면 `--state`가 우선합니다.

## 작업 관리

| 명령 | 역할 |
|---|---|
| `start --spec <파일>` | 완료 조건이 고정된 새 작업을 생성합니다. `--platform`, `--session`을 지정하면 해당 호스트 세션에 연결합니다. |
| `tasks` | 저장된 작업 목록, 메모, 세션 연결 후보를 읽기 전용으로 조회합니다. 기록된 상태가 없으면 빈 목록을 반환합니다. |
| `attach <작업ID> --platform <호스트> --session <세션>` | 기존 작업을 현재 활성 세션으로 전환 연결합니다. 이전 검사 결과와 메모는 그대로 보존됩니다. |
| `status <작업ID>` | 지정된 작업의 현재 검사 결과, 작업 명세, 진행 메모를 조회합니다. |
| `checkpoint <작업ID> --note <파일>` | 작업 재개용 메모를 저장합니다. 단, 메모 저장이 검사 통과를 대체하지는 않습니다. |

## 검증 실행

| 명령 | 역할 |
|---|---|
| `verify <작업ID>` | 등록된 검증 명령들을 순차 실행하며, 첫 번째 실패 시 즉시 중단합니다. |
| `verify <작업ID> --all` | 일부 검사가 실패하더라도 등록된 모든 검증을 끝까지 실행합니다. |
| `verify <작업ID> --check <검사ID>` | 지정된 특정 검사만 선별 실행합니다. 결과는 `requested_verified` 필드에 별도 표시됩니다. |
| `recover <작업ID>` | 비정상 중단된 검사의 잔여 실행 기록을 정리합니다. 해당 검사 프로세스가 여전히 살아 있다면 정리를 거부합니다. |

## 완료 증명서 및 재현

| 명령 | 역할 |
|---|---|
| `certify <작업ID> --output <파일>` | 완료 주장과 실제 실행 명령, 종료 코드, 파일 지문을 단일 증명서 파일로 패키징합니다. 미검증 상태라면 종료 코드 1을 반환합니다. |
| `replay --certificate <파일>` | 증명서 파일만 읽어 검증 명령을 다시 실행합니다. 로컬 상태 DB에 의존하지 않습니다. |

`replay`의 종료 코드는 증명서 판정 결과와 일치합니다. `0`은 `pass`(재현 성공 및 범위 완전), `1`은 `invalid`(재현 실패 또는 불일치), `2`는 `inconclusive`(재현되었으나 미확인 범위 잔존)를 나타냅니다.

## 기타 유틸리티

| 명령 | 역할 |
|---|---|
| `inspect <경로...>` | 여러 텍스트 파일을 한 번에 읽고 라인 범위, 잘림 여부, 파일 해시를 함께 반환합니다. |
| `environment [--expect <파일>]` | 로컬 Python 프로세스의 OS·아키텍처·런타임·실행 파일 존재를 관찰하고 필요조건과 비교합니다. 불일치는 종료 코드 1이며 관찰만 하면 `matches`는 `null`입니다. |
| `unittest [--start-directory <폴더>] [--pattern <패턴>] [--require <시험ID>]` | Python unittest를 별도 프로세스에서 실행하고 필수 시험 ID의 성공을 확인합니다. `--require`는 반복할 수 있으며 실패·누락·필수 skip은 종료 코드 1입니다. |
| `pause --platform <호스트> --session <세션> --reason <사유>` | 사용자 명시적 확인 대기나 외부 리소스 한도로 인해 작업을 일시 정지할 때 사용합니다. |
| `resume --platform <호스트> --session <세션>` | 일시 정지되었던 세션 연결을 다시 활성화합니다. |

## 환경 필요조건 비교

```bash
python3 "$GTG" environment
python3 "$GTG" environment --expect verification-environment.json
```

조건 파일은 확인된 작업 요구에서 에이전트가 작성합니다. `system`, `machine`, `python_version`, `python_implementation`은 문자열을 정확히 비교하며, `executables`에는 PATH에서 찾을 실행 파일 이름 목록을 지정합니다. 알 수 없는 필드·빈 조건·인자나 경로가 있는 실행 파일 이름은 거부합니다. 일치하면 종료 코드 0, 불일치나 잘못된 조건이면 1입니다. 실행 파일을 실행하거나 설치하지 않습니다.

관찰 범위는 현재 Python 프로세스입니다. 컨테이너·원격 서버·물리 기기의 조건을 대신하지 않습니다. `target_compatibility_verified`와 `resource_limits_verified`는 항상 `false`이며, 파일 존재만으로 API 동작이나 제품 호환성을 판정하지 않습니다. 조건 파일을 검증 계약에 사용하면 `watch`에도 넣고, 환경 변경 뒤에는 파일이 같아도 다시 검증합니다. [적용 절차](../../profile/skills/gtg-build/references/critical-review.md).

## Python 필수 시험

```bash
python3 "$GTG" unittest --workspace . --start-directory tests
```

`--require`에는 발견된 실제 전체 시험 ID를 지정합니다. 실행 0개·모든 시험 skip·필수 ID 누락·필수 ID skip/expectedFailure·관측 누락은 통과하지 않습니다. 선택적 시험의 skip은 결과에 남기며, 성공한 시험이 하나도 없으면 실패합니다. 종료 코드 0은 관측된 시험의 성공이며 PRD 전체의 의미나 미실행 경로의 API 존재까지 증명하지 않습니다.

프로젝트 인터프리터를 사용하고 시간 제한은 작업 계약의 `timeout_seconds`로 둡니다. 새 임시 바이트코드 캐시 경로에서 시작하며 `.pyc`를 쓰지 않습니다. 원시 하위 프로세스 출력도 stderr로 보내 JSON 결과와 섞이지 않게 합니다. 관측 JSON은 최대 256KiB이며 초과·손상·조기 종료는 실패입니다. 시험 코드는 일반 프로젝트 코드 권한으로 실행하며 OS 샌드박스가 아닙니다.

## 결과물 검사

| 명령 | 역할 |
|---|---|
| `structure [경로...] [--base <리비전>] [--max-lines <줄>] [--max-methods <개수>]` | 기준 리비전(기본 HEAD)과 작업 트리를 비교해 이번에 바뀐 코드만 봅니다. 새로 넣은 줄의 TODO·FIXME, 본문이 빈 함수, 기준을 넘어 커진 파일, 메서드가 기준을 넘어 늘어난 클래스, 구문 오류가 있으면 종료 코드 1입니다. |
| `prose [문서...] [-] [--text <글>] [--original <원문>] [--register <갈래>] [--min-score <점수>]` | 한국어·영어 문서의 상투구·과장·번역투·대구·도치·단조로운 리듬과 높임을 줄 번호와 함께 찾고 0~100점과 A~D 등급을 매깁니다. `--register`로 general·academic·everyday·literary 갈래를 고르고, `--min-score`로 기준 점수를 겁니다. `-`는 표준 입력을, `--text`는 명령줄에 준 글을 각각 문서 하나로 검사합니다(파일과 섞어 쓸 수 있고 합쳐 64개까지). `--original`은 윤문한 문서 하나를 원문과 견줘 수치·인용·URL·코드가 바뀌었는지와 바뀐 단어 비율을 확인하며 결과의 `fidelity`에 담습니다. 차단 항목이나 기준 미달 문서, 읽지 못한 문서(빈 글 포함)가 있으면 종료 코드 1입니다. |

```bash
python3 "$GTG" structure --workspace . --base START_COMMIT
python3 "$GTG" prose --workspace . README.md
python3 "$GTG" prose --workspace . --register academic --original draft.md polished.md
python3 "$GTG" prose --register everyday - <<'EOF'
내일 3시에 봐요. 늦으면 연락 줘요.
EOF
```

두 검사 모두 결과의 `findings`에 `block`(차단)과 `review`(검토) 신호를 나눠 담습니다. 종료 코드는 차단 신호만 따르고, 검토 신호는 사람이 문맥을 보고 판단할 몫으로 남깁니다.

`structure`의 기본값은 파일 400줄, 클래스 메서드 20개입니다. 이미 기준을 넘은 파일은 30줄 넘게 늘거나 새 최상위 정의가 생길 때만 막으므로 큰 파일의 버그 수정은 막지 않고, 시험 파일의 크기 신호는 검토로만 남깁니다. 구현이 하나뿐인 추상 클래스, 인자를 그대로 넘기는 래퍼, 부르는 곳이 없는 새 정의, 긴 함수는 검토 신호입니다. Git 저장소가 아니면 `--base none`과 경로를 함께 지정하며, 이때는 지정한 파일 전체를 새 코드로 봅니다. Python 외 언어는 줄 수와 주석 표식만 확인하고 그 파일 목록을 `structure_unanalyzed`에 적습니다.

`prose`는 코드 블록과 인라인 코드, URL, 문서 머리말을 보지 않습니다. 지워도 뜻이 줄지 않는 상투구는 한 번만 나와도 차단하고, `~에 대해`·`~를 통해`처럼 사람도 자주 쓰는 표현은 한 문단에 세 번 넘게 몰릴 때만 검토 신호로 알립니다. 사실 여부와 글의 품질 자체는 판정하지 않습니다. 점수는 감점(차단 3점, 검토 1점)을 문장 10개 단위로 나눈 밀도로 계산합니다. 사람 글에 더 흔하게 측정된 높임 혼용과 사람 초안에만 나오는 맞춤법 오류는 알리기만 하고 감점하지 않습니다. 짧은 문장 연쇄와 같은 첫머리 반복은 일반·학술 갈래에서는 감점하고, 짧은 문장이 정상인 시와 구어 일상 글에서는 알리기만 합니다. 문서 전체·문단 안 횟수 기준은 20문장·6문장 분량에서 잰 값이며 더 긴 글은 비례해 늘리고, 시와 차단 규칙에서는 늘리지 않습니다. 분량은 산문은 문장 수, 제목·목록은 줄 수, 마침표가 없거나 행이 짧은 시는 줄 수로 셉니다. 사람·LLM 한국어 글로 잰 결과는 [3.3.0 검증 기록](../verification/3.3.0.md)과 [3.2.0 검증 기록](../verification/3.2.0.md)에 있습니다.

`--original`의 차단 기준은 퍼센트·소수·세 자리 이상 수치, 8자 이상 따옴표 인용, URL, 코드가 원문과 달라진 경우이고, 한두 자리 자연수와 영문 표기의 변화는 검토 신호입니다. 바뀐 단어가 원문의 30%를 넘으면 검토, 50%를 넘으면 지운 문장을 보고하도록 안내하는 검토, 80%를 넘으면(40단어 이상) 새로 쓴 글이라 차단합니다. 이 발견은 문체 점수에 들어가지 않습니다.

## 교훈 기록

| 명령 | 역할 |
|---|---|
| `lesson --text <문장> --evidence <근거>` | 검증에서 드러난 저장소별 사실을 `.gtg/lessons.jsonl`에 남깁니다. 근거는 작업공간의 실제 파일(`path` 또는 `path:줄`)이나 `http`·`https` URL이며 1~5개를 붙입니다. 같은 문장은 한 번만 저장하고 최근 100개만 유지합니다. |
| `lessons [--limit <개수>]` | 남은 교훈을 최근 것부터 보여 줍니다. |

턴 시작 훅은 최근 교훈 다섯 개를 "지시가 아닌 기록"으로 안내에 붙입니다. 교훈은 검증을 대신하지 않으며, 모델은 쓸 때마다 현재 파일로 다시 확인해야 합니다.

## 플랫폼 훅

호스트 환경이 `hook <호스트> <이벤트>` 규격으로 호출합니다. 표준 입력(stdin)으로 호스트 이벤트 페이로드를 전달받고 표준 출력(stdout)으로 처리 결과 JSON을 응답합니다. 사용자가 수동으로 호출하지 않습니다. 세부 계약은 [훅 계약](hooks.md) 문서를 참고하세요.
