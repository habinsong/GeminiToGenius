# 명령 목록

설치된 패키지 안의 `run.py`가 진입점입니다. 모델이 이 명령을 직접 실행하며, 사용자가 입력할 일은 없습니다. 아래 예시의 `$GTG`는 설치된 `run.py`의 절대 경로입니다.

```bash
GTG=~/.gemini/config/plugins/geminitogenius/run.py
```

모든 작업 명령은 `--workspace`를 받습니다. 생략하면 현재 폴더를 씁니다. 전역 옵션 `--state`로 상태 DB 경로를 직접 지정할 수 있고, 둘 다 주면 `--state`가 이깁니다.

## 작업

| 명령 | 하는 일 |
|---|---|
| `start --spec <파일>` | 완료 조건을 고정한 작업을 만듭니다. `--platform`·`--session`을 함께 주면 호스트 세션에 연결합니다. |
| `tasks` | 저장된 작업·메모·연결 후보를 읽기 전용으로 조회합니다. 상태가 없으면 빈 목록입니다. |
| `attach <작업ID> --platform <호스트> --session <세션>` | 기존 작업을 현재 세션으로 옮깁니다. 검사 결과와 메모는 그대로 둡니다. |
| `status <작업ID>` | 현재 검사 결과, 명세, 메모를 봅니다. |
| `checkpoint <작업ID> --note <파일>` | 재개용 메모를 남깁니다. 검사 성공을 대신하지 않습니다. |

## 검증

| 명령 | 하는 일 |
|---|---|
| `verify <작업ID>` | 등록된 검사를 실행합니다. 첫 실패에서 멈춥니다. |
| `verify <작업ID> --all` | 실패해도 끝까지 실행합니다. |
| `verify <작업ID> --check <검사ID>` | 지정한 검사만 실행합니다. 결과는 `requested_verified`로 따로 나옵니다. |
| `recover <작업ID>` | 중단된 실행 기록을 정리합니다. 검사 프로세스가 살아 있으면 거부합니다. |

## 증명서

| 명령 | 하는 일 |
|---|---|
| `certify <작업ID> --output <파일>` | 완료 주장을 명령·종료 코드·파일 지문에 묶습니다. 미검증이면 종료 코드 1입니다. |
| `replay --certificate <파일>` | 증명서만 읽어 명령을 다시 실행합니다. 상태 DB를 쓰지 않습니다. |

`replay`의 종료 코드는 판정과 같습니다. `0`은 `pass`, `1`은 `invalid`(재현 실패), `2`는 `inconclusive`(재현했지만 확인하지 못한 범위가 남음)입니다.

## 그 밖

| 명령 | 하는 일 |
|---|---|
| `inspect <경로...>` | 여러 텍스트 파일을 한 번에 읽고 범위·잘림·해시를 돌려줍니다. |
| `pause --platform <호스트> --session <세션> --reason <사유>` | 사용자 확인이나 외부 한도로 멈출 때 씁니다. |
| `resume --platform <호스트> --session <세션>` | 멈춘 연결을 다시 엽니다. |

## 훅

`hook <호스트> <이벤트>` 형태로 호스트가 부릅니다. 표준 입력으로 호스트 페이로드를 받고 표준 출력으로 JSON을 냅니다. 사람이 직접 부를 일은 없습니다. 자세한 것은 [훅 계약](hooks.md)에 있습니다.
