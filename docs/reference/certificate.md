# 완료 증명서

작업을 끝났다고 말할 때, 주장과 근거를 한 파일로 묶습니다. 받는 쪽은 상태 DB 없이 이 파일만으로 다시 확인할 수 있습니다.

```bash
python3 "$GTG" certify TASK_ID --output .gtg/certificate.json
python3 "$GTG" replay --certificate .gtg/certificate.json --workspace .
```

## 들어 있는 것

완료 조건마다 실제로 실행한 명령, 종료 코드, 검증 대상 파일의 지문이 들어갑니다. 통과하지 않은 검사에는 지문을 붙이지 않습니다. 미검증 작업을 `certify`하면 종료 코드 1과 `verified: false`가 나옵니다.

본문 전체에 `digest`가 걸려 있어 한 글자라도 고치면 `replay`가 거부합니다.

## 판정

`replay`는 증명서와 현재 파일만 씁니다. 명령을 다시 실행해 종료 코드 0과 기록된 지문이 모두 재현될 때만 `reconstructed: true`입니다.

| 판정 | 종료 코드 | 뜻 |
|---|---|---|
| `pass` | 0 | 재현했고 확인 범위도 완전합니다. |
| `invalid` | 1 | 재현이 깨졌습니다. 증명서가 현재 상태를 뒷받침하지 못합니다. |
| `inconclusive` | 2 | 재현했지만 확인하지 못한 범위가 남았습니다. |

**`inconclusive`를 통과로 바꿔 보고하지 않습니다.** 파일이 달라져 깨진 경우에는 `reason: "fingerprint"`가 붙습니다.

증명서에 적힌 작업공간과 다른 폴더에서 실행하려면 명령을 직접 읽어 본 뒤 `--trust-commands`를 줍니다.

## 확인하지 못한 범위

증명서에는 두 필드가 더 있습니다.

- `unverified_scope` — 통과한 검사가 있는데도 **어떤 검사도 실행하지 않은** 검증 대상 파일입니다.
- `coverage_complete` — 거짓이면 위 목록은 하한일 뿐입니다. 빈 목록을 "전부 검증함"으로 읽으면 안 됩니다.
- `unobservable_scope` — 위 판단을 막은 파일입니다. 셸 스크립트나 Go·Rust처럼 실행을 관찰할 수 없는 코드가 범위에 있으면 여기 나옵니다.

무엇을 관찰할 수 있고 무엇을 못 하는지는 [실행 관측](../architecture/coverage.md)에 있습니다.

## 이 증명서가 말하지 않는 것

등록된 검사 범위 안에서 재현 가능하다는 것까지입니다. 그 검사가 사용자 요구를 다 담았는지는 증명하지 않습니다. 완료 보고에는 판정 값을 그대로 적고, 검사 설계의 적절성은 따로 설명해야 합니다.
