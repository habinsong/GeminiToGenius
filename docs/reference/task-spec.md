# 작업 명세

작업공간의 `.gtg/task.json`에 씁니다. 모델이 현재 요청을 보고 만들며 사용자가 손댈 필요는 없습니다.

```json
{
  "schema_version": 1,
  "goal": "현재 요청을 검증 가능한 결과로 적습니다.",
  "max_resumes": 2,
  "checks": [
    {
      "id": "regression",
      "criterion": "수정한 실패 경로가 해결되고 기존 동작이 유지됩니다.",
      "argv": ["python3", "-m", "unittest", "discover", "-s", "tests"],
      "watch": ["src", "tests"],
      "timeout_seconds": 120
    }
  ]
}
```

## 필드

| 필드 | 설명 |
|---|---|
| `goal` | 이 작업이 끝났다고 말할 수 있는 상태를 적습니다. |
| `checks[].id` | 작업 안에서 겹치지 않는 이름입니다. |
| `checks[].criterion` | 이 검사가 무엇을 보증하는지 사람 말로 적습니다. |
| `checks[].argv` | 실제로 실행할 명령입니다. 셸을 거치지 않고 그대로 실행합니다. |
| `checks[].watch` | 결과를 무효로 만들어야 하는 소스·테스트·설정 경로입니다. |
| `checks[].timeout_seconds` | 기본값 120입니다. |
| `max_resumes` | 자연 종료를 되돌리는 최대 횟수입니다. 기본 2, 상한 8. |

## 거부되는 것

`true`, `:`, `echo`, `printf`, `yes`, `sleep`, `cat`은 검증 명령으로 등록할 수 없습니다. 무엇을 넣어도 성공하거나 입력을 되돌려 줄 뿐이라 아무것도 확인하지 못합니다. 셸을 거친 우회까지 막지는 못하므로, 실제 방어는 [증명서](certificate.md)의 독립 재실행입니다.

심볼릭 링크와 비밀 파일은 검증 대상으로 쓸 수 없습니다.

## `watch` 범위 상한

**작업 전체의 `watch` 범위는 파일 20,000개·200MB 이하여야 합니다.** 검사마다가 아니라 작업 전체가 함께 쓰는 예산이며, 같은 범위는 한 번만 셉니다. 넘으면 `start`에서 거부합니다.

훅이 매 턴 이 범위를 다시 읽기 때문에 둔 제한입니다. 실측하면 파일 19,000개 범위를 검사 3개가 나눠 가질 때 훅 왕복이 3.4초까지 늘어납니다. 호스트가 주는 시간이 5초라 여유가 크지 않습니다.

`node_modules`, `target`, `build` 같은 의존성과 생성물을 빼고 실제 소스와 테스트만 지정하면 걸릴 일이 없습니다. `.gtg` 상태 파일과 Python 캐시는 내용 비교에서 빠집니다.

## 등록 뒤에 파일이 바뀌면

통과한 검사라도 `watch` 안의 파일이 바뀌면 `stale`이 됩니다. 저장된 성공을 현재 상태의 근거로 쓰지 않기 위한 것입니다. 다시 `verify`하면 됩니다.
