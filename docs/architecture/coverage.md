# 실행 관측

검증 명령을 실행할 때 실제로 어떤 코드 파일이 호출되었는지 런타임 수준에서 추적하여 기록합니다. 통과한 검증이 실제로는 어떤 대상 코드를 실행하지 않았는지 확인하기 위함입니다.

## 추적 메커니즘

Python 환경에서는 임시 디렉터리에 생성한 `sitecustomize.py`를 `PYTHONPATH` 최우선 순위에 배치하여 인터프리터 부트스트랩 시점에 계측을 시작합니다. Python 3.12+에서는 `sys.monitoring`의 `PY_START` 이벤트만 청취하며 최초 콜백 시 즉시 `DISABLE`을 반환하므로 추가 오버헤드 없이 계측을 종료합니다. 이를 지원하지 않는 환경에서는 `sys.settrace` 기반으로 안전하게 폴백합니다.

Node.js 환경에서는 `--require` 플래그로 부트스트랩 스크립트를 주입하고 `module.registerHooks`의 `load` 이벤트를 가로채 실제로 로드된 파일들을 수집합니다.

검증 명령이 내부에서 생성한 자식 프로세스 역시 동일한 환경 변수를 상속받아 일관되게 관측됩니다. 사용자 환경의 기존 `sitecustomize`를 덮어쓰지 않고 순차적으로 실행합니다.

## 지원 런타임 및 확장자

| 확장자 | 관측 지원 상태 |
|---|---|
| `.py`, `.js`, `.mjs`, `.cjs` | 기본적으로 완전 관측을 지원합니다. |
| `.ts`, `.mts`, `.cts` | 런타임(Node.js 등)이 직접 소스를 실행할 때만 관측합니다. |
| `.tsx`, `.jsx`, `.go`, `.rs`, `.sh` 등 | 직접 관측 대상에서 제외됩니다. |

TypeScript의 경우 Node.js 최신 런타임이 `.ts` 파일을 트랜스파일 없이 직접 실행할 때 정상 캡처함을 확인했습니다. 다만 사전에 빌드된 컴파일 산출물(dist/build)을 실행한 경우에는 원본 TypeScript 소스가 미실행된 것으로 단정하지 않습니다.

셸 스크립트는 안정적인 추적이 어렵고 불완전한 부분 관측의 오류를 피하기 위해 관측 불가(`unobservable`)로 명시합니다.

## 산출 메트릭 필드

| 필드명 | 의미 |
|---|---|
| `executed_watch` | 해당 검증 명령 실행 중 실제로 호출된 검사 대상 파일 목록 |
| `unexecuted_watch` | 검증은 통과했으나 실제로는 실행되지 않은 검사 대상 파일 목록 |
| `unobservable_watch` | 런타임 제약으로 인해 실행 여부를 판단할 수 없었던 파일 목록 |

`unexecuted_watch`가 `null`인 경우는 관측 불가능한 언어가 포함되어 있거나 대상 파일 수가 너무 많아 전수 조사가 제한된 경우입니다. 전자의 경우에만 `unobservable_watch`에 해당 파일 목록이 채워집니다.

## 한계와 해석 기준

실행 관측은 파일 단위로만 이루어집니다. 파일이 실행되었다는 사실이 해당 파일의 모든 코드 라인이나 로직 분기가 검증되었음을 뜻하지는 않으며, 코드 커버리지(라인/브랜치 커버리지)를 대체하지는 않습니다. 문서나 설정 파일 같은 비실행 정적 파일은 관측 대상이 아닙니다.
