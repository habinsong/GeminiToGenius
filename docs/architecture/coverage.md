# 실행 관측

검증 명령을 실행하는 동안 어떤 코드 파일이 실제로 호출되었는지 런타임에서 추적해 기록합니다. 통과한 검증이 실행하지 않은 대상 코드를 확인하기 위한 기능입니다.

## 추적 메커니즘

Python 환경에서는 임시 디렉터리에 만든 `sitecustomize.py`를 `PYTHONPATH`의 맨 앞에 두어 인터프리터가 시작될 때 계측을 켭니다. Python 3.12+에서는 `sys.monitoring`의 `PY_START` 이벤트만 받고 첫 콜백에서 바로 `DISABLE`을 반환하므로 추가 오버헤드 없이 계측이 끝납니다. 그 외 환경에서는 `sys.settrace` 기반 방식으로 바뀝니다.

Node.js 환경에서는 `--require` 플래그로 부트스트랩 스크립트를 주입하고 `module.registerHooks`의 `load` 이벤트를 가로채 실제로 로드된 파일을 수집합니다.

검증 명령이 만든 자식 프로세스도 같은 환경 변수를 상속받으므로 관측 대상입니다. 사용자 환경에 이미 `sitecustomize`가 있으면 덮어쓰지 않고 이어서 실행합니다.

## 지원 런타임 및 확장자

| 확장자 | 관측 지원 상태 |
|---|---|
| `.py`, `.js`, `.mjs`, `.cjs` | 기본적으로 완전 관측을 지원합니다. |
| `.ts`, `.mts`, `.cts` | 런타임(Node.js 등)이 직접 소스를 실행할 때만 관측합니다. |
| `.tsx`, `.jsx`, `.go`, `.rs`, `.sh` 등 | 직접 관측 대상에서 제외됩니다. |

TypeScript는 Node.js 최신 런타임이 `.ts` 파일을 트랜스파일 없이 직접 실행할 때 정상적으로 관측되는 것을 확인했습니다. 다만 미리 빌드한 컴파일 산출물(dist/build)을 실행한 경우, 원본 TypeScript 소스를 미실행으로 단정하지 않습니다.

셸 스크립트는 안정적으로 추적하기 어렵고 일부만 관측해 생기는 오류를 피하기 위해 관측 불가(`unobservable`)로 표시합니다.

## 산출 메트릭 필드

| 필드명 | 의미 |
|---|---|
| `executed_watch` | 해당 검증 명령 실행 중 실제로 호출된 검사 대상 파일 목록 |
| `unexecuted_watch` | 검증은 통과했으나 실제로는 실행되지 않은 검사 대상 파일 목록 |
| `unobservable_watch` | 런타임 제약으로 인해 실행 여부를 판단할 수 없었던 파일 목록 |

`unexecuted_watch`가 `null`인 경우는 관측 불가능한 언어가 포함되어 있거나 대상 파일 수가 너무 많아 전수 조사가 제한된 경우입니다. 전자의 경우에만 `unobservable_watch`에 해당 파일 목록이 채워집니다.

## 결과를 해석하는 기준

실행 관측은 파일 단위로만 이루어집니다. 파일이 실행되었다고 해서 모든 코드 라인과 로직 분기가 검증된 것은 아니므로, 코드 커버리지(라인/브랜치 커버리지)를 대신할 수 없습니다. 문서나 설정처럼 실행되지 않는 정적 파일은 관측 대상에서 빠집니다.
