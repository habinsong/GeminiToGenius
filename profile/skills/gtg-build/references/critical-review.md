# 적대적 검토

목적은 근거에 맞는 엄밀한 기술적 판단이며, 어떤 제안이든 성공을 맹목적으로 전제하거나 상투적인 면책 문구로 검토를 대신하지 않고 사실에 부합하면 채택하되 근거가 충돌하면 수정하거나 보류합니다.

## 주장 목록

보고나 설명에 들어갈 사실 주장을 한 줄씩 정리합니다. 코드 동작과 API 존재 여부, 버전 호환성, 성능 수치, 완료 여부가 대상입니다. 설명 대부분이 맞더라도 중간에 근거 없는 문장이 끼어 있으면 해당 문장도 따로 확인합니다. 사용자 요구와 선택 제안을 구분하여 제안을 확정 요구로 바꾸지 않습니다.

## 반박 시도

보고에 넣을 핵심 주장만 대상으로 합니다. 주장마다 "틀렸다면 무엇이 보여야 하는가"를 먼저 정의하고 실제로 확인합니다. 작은 수정은 고친 줄과 직접 관련된 시험을 한 번 확인하면 충분하며, 확인을 이유로 다른 폴더와 파일을 새로 훑지 않습니다.

1. 초안을 다시 읽지 말고 원본 파일을 다시 엽니다. 해당 줄을 확인하고 명령을 다시 실행하며 공식 문서 원문을 검토합니다. 자기 답을 근거로 삼으면 동일한 착오가 되풀이됩니다.
2. 저장소 밖 사실은 독립된 출처 두 곳이 일치하는지 확인합니다.
3. 반례를 직접 시도합니다. 경계값과 빈 입력, 오류 경로 가운데 해당하는 조건을 실행합니다.
4. 시험의 유효성을 점검합니다. 수정한 부분을 잠시 되돌렸을 때 시험이 실패해야 버그를 정상 포착하는 시험이며, 확인 후 코드는 원래대로 복구합니다.
5. 결과를 확인됨, 반박됨, 미확인으로 구분합니다. 반박된 주장은 수정하거나 삭제하고 미확인은 미확인으로 명시합니다.

## 구현 가능성과 실사용 조건

본격적인 구현 전에 핵심 API와 권한, 데이터 규모, 자원 조건을 확인합니다. 논문 결과나 비공개 API를 즉시 사용 가능한 제품 기능으로 간주하지 않습니다. 가능 여부와 조건부 가능을 구분하고 불확실한 전제에는 최소 단위의 확인 실험을 둡니다.

목표 환경과 시험 환경을 대조합니다. 운영체제와 런타임, 권한과 네트워크 조건의 차이를 확인해야 합니다. 목 데이터나 에뮬레이터에서 거둔 성공을 실제 사용자 환경의 성공으로 확대 해석하지 않습니다.

로컬 실행 환경이 핵심 전제이면 설치된 실행기로 관찰하고 필요조건과 비교합니다.

```bash
python3 "$GTG_RUNNER" environment
python3 "$GTG_RUNNER" environment --expect verification-environment.json
```

조건 파일은 에이전트가 확인한 요구로 직접 작성합니다. Linux와 Git이 필요한 경우 아래와 같이 정의합니다.

```json
{"system": "Linux", "executables": ["git"]}
```

`system`, `machine`, `python_version`, `python_implementation`은 관찰값과 비교하고 `executables`는 PATH 존재 여부만 확인합니다.

## 사용자 의견과 지적

사용자가 제안하거나 반박할 때도 근거로 판단합니다. 사실에 부합하면 따르고 근거와 다르면 차이점을 근거와 함께 설명합니다. 실수를 지적받았을 때는 사과를 길게 늘어놓지 않고 틀린 점을 한 문장으로 인정한 뒤 수정하여 다시 확인합니다.

실수를 다음 세션에서 되풀이하지 않도록 확인된 사실을 교훈으로 남깁니다. 일반론을 지양하고 근거 파일이나 원문 URL을 함께 기록합니다.

```bash
python3 "$GTG_RUNNER" lesson --workspace /absolute/project/path --text "sdk.py에는 export_rows가 없고 실제 함수는 write_rows(rows, path)입니다." --evidence sdk.py:12
python3 "$GTG_RUNNER" lessons --workspace /absolute/project/path
```

근거는 실제 파일이나 URL이어야 하며 중복 문장은 한 번만 저장됩니다.

## 보고

검사 통과와 실사용 조건 확인을 분리하여 기록합니다. 등록한 명령의 성공을 자연어 설명 전체의 진실로 일반화하지 않습니다.

메모에는 확인된 사실과 남은 검증, 다음 행동을 나누어 기록합니다. 이전 세션의 메모를 맹신하지 않고 재개할 때 원본 파일과 검증 결과를 다시 확인합니다.
