# 화면 구현과 검증

현재 화면과 제품의 주요 작업을 먼저 확인하고 사용자가 막히는 지점을 짚습니다. 화면 구조는 정보 우선순위와 동선에서 나오며, 미리 정해 둔 틀에 맞추지 않습니다. 기존 디자인 시스템이 있다면 이를 따릅니다.

필요한 경로와 로딩, 빈 상태, 오류, 복구 동작을 계획합니다.

실제로 동작하는 인터랙션을 만듭니다. 가짜 지표나 누를 수 없는 버튼, 제품과 무관한 장식은 넣지 않습니다. 화면 문구는 사용자가 상황과 다음 행동을 바로 알 수 있도록 명확하게 작성합니다.

지원되는 브라우저나 앱 도구로 실제 화면을 확인합니다. 좁은 화면과 넓은 화면의 넘침, 키보드 포커스, 읽기 순서, 뒤로 가기 동작을 점검합니다.

DOM 단어나 계획서 분량으로 화면 품질을 판정하지 않습니다. 관찰 도구가 없어 확인하지 못한 항목은 미검증으로 남깁니다.

화면이 생성되었다는 사실만으로 성공이라 단정하지 않습니다. 목 데이터나 에뮬레이터 환경의 결과를 실제 브라우저의 성공으로 넓히지 않으며 실사용 조건이 불확실하면 [적대적 검토](../gtg-build/references/critical-review.md)를 적용합니다.
