# 사례에 주어진 근거

## 배포 요구

- Linux aarch64, Python 3.11, 논리 CPU 2개, RAM 1GiB, GPU 없음.
- 인터넷과 관리자 권한을 사용할 수 없습니다. 추가 유료 장비 구매도 현재 범위 밖입니다.
- 최대 사진 30,000개, 파일당 최대 48MiB를 다룹니다. 목록에는 메타데이터만 읽으면 됩니다.
- USB 연결 해제 뒤 재연결이 가능해야 합니다. 목표 지연·처리량의 수치는 아직 정하지 않았습니다.

## 제공된 시험 기록

- 개발기: macOS arm64, RAM 32GiB. CPU 시간·메모리 상한을 적용하지 않았습니다.
- 합성 표본: 사진 12개, 각 512×512, 2MiB 이하. 가상 USB 어댑터를 사용했습니다.
- 단위 검사 8개 통과. 이 중 PNG 시그니처 검사가 2개입니다.
- 이 표본에서 목록 조회 평균 35ms. 백분위 지연, 최대 메모리, 오류율은 기록하지 않았습니다.
- Linux 대상 기기·최대 데이터·실제 USB 복구 시험은 수행하지 않았습니다.
- PNG 전체 디코딩, 다른 이미지 형식, 보안 검사는 수행하지 않았습니다.

## 장애 접수

USB 목록이 한 번 비었다는 제보만 있습니다. 로그·재현 절차·발생 기기의 OS와 권한 정보는 없습니다. SDK 결함인지 케이블·권한·사용 절차 문제인지는 확인되지 않았습니다.
