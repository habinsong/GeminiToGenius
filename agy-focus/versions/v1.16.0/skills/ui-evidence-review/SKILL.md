# UI 증거 검토

완성된 화면이나 기존 화면을 근거로 검토합니다. 구현 규율은 `interface-implementation`에 둡니다.

1. 실제 사용자 목표, 현재 상태, 다음 행동, 기존 디자인 시스템을 먼저 확인합니다. 근거가 없으면 새 시각 언어를 발명하지 않습니다.
2. 화면이 기능보다 카드·그라데이션·가짜 데이터·AI 배지를 앞세우는지 확인합니다. 도메인 근거 없는 우주·로봇·관제 화면·채팅창·추상 아이콘은 제거합니다.
3. 헤드라인·레이블·링크가 기능과 다음 행동을 직접 설명하는지 확인합니다. 미래 약속·기능 없는 헤드라인·빈 칭찬·긴 서술은 제거합니다.
4. 레이아웃·서체·색상·여백·모서리·그림자·애니메이션은 기능·위계·기존 시스템·접근성 중 하나로 설명할 수 있을 때만 통과시킵니다.
5. 가장 좁은 지원 폭과 넓은 화면에서 읽기 순서, 키보드 포커스, 색상 외 상태 표시, 가려진 조작, 오버플로우, 불필요한 움직임을 확인합니다.
6. 실제 화면을 렌더링하거나 조작해 확인합니다. 화면을 못 봤으면 시각 품질을 통과로 표현하지 않습니다.

결과에는 바꾼 UI 요소, 실제 확인한 화면 상태, 확인하지 못한 시각 검증만 짧게 남깁니다.
