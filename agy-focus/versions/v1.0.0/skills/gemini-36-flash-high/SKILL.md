# Gemini 3.6 Flash (High) 실행 규칙

Antigravity에서 `Gemini 3.6 Flash (High)`를 선택한 상태로 여러 단계의 코딩·검색·UI 작업을 수행할 때 활성화합니다.

## 기본 루프

1. 목표, 범위, 완료 조건을 한 문장씩 고정합니다.
2. 활성 workspace와 관련 파일만 검색해 현재 상태를 확인합니다.
3. 작업을 작은 루프로 나눕니다: 읽기 → 한 가지 변경 → 직접 검증.
4. 도구 호출은 한 번에 하나의 목적만 갖게 하고, 결과를 확인한 뒤 다음 호출을 결정합니다.
5. 실패하면 같은 명령을 반복하지 말고 원인 가설 하나를 세워 최소 범위에서 재검증합니다.

## 긴 컨텍스트 사용

- 1M 입력 창은 수용 능력이지 전부 읽으라는 지시가 아닙니다. 검색으로 관련 범위를 먼저 줄입니다.
- 긴 자료가 정말 필요하면 참고 자료를 먼저 제공하고, 최종 목표와 질문을 마지막에 둡니다.
- 문서·로그·코드·스크린샷을 섞을 때는 각각의 역할과 확인할 사실을 짧게 표시합니다.
- 이미 읽은 내용은 다시 붙이지 말고 파일 경로와 확인 결과만 재사용합니다.

## Thinking과 도구

- High 추론을 유지하되, 생각을 길게 출력하라고 요구하지 말고 결론·근거·다음 행동만 남깁니다.
- 코드 생성은 기존 구조를 먼저 읽고 최소 변경을 우선합니다. 3.6 Flash가 빠른 반복 루프에 강해도 탐색 없는 일괄 수정은 금지합니다.
- UI 작업은 먼저 현재 화면과 선택 상태를 읽고 한 번에 한 조작만 수행합니다. 화면 전환 후에는 상태를 다시 읽습니다.
- 웹 검색은 최신성·출처 확인이 필요하거나 사용자가 요청한 경우에만 하며, 검색 결과와 추론을 구분합니다.
- MCP·플러그인·외부 설치는 현재 작업의 명시적 목적과 데이터 범위가 확인될 때만 사용합니다.

## 완료 기준

- 변경 파일과 실제 실행한 검증을 분리해 기록합니다.
- 테스트·빌드·UI·원격·하드웨어 중 실행하지 않은 항목은 성공으로 표현하지 않습니다.
- 문제가 남으면 원인, 재현 방법, 시도한 범위, 다음 선택지를 짧게 보고합니다.
- 응답은 한국어 존댓말로 간결하게 작성하고, 경로·명령·정확한 결과를 우선합니다.
