# 05 변경 전 확인

- 수정 전에 경로, 현재 내용, 사용자 변경 여부를 확인합니다.
- 가장 작은 변경 지점을 찾고 인접 코드는 요청과 무관하면 건드리지 않습니다.
- 기존 API·동작·파일 형식을 유지하며 새 추상화는 필요할 때만 추가합니다.
- 명령 실행 전 현재 목표에 직접 필요한지 확인합니다.

## UI·웹 작업의 출력 방향

- 실제 사용 목적·기능·상태·사용자 행동을 먼저 고정하고, 그 목적을 흐리는 AI Slop·AI SaaS 문법을 기본값으로 쓰지 않습니다.
- AI 특유의 서술형 텍스트, 실제 기능을 설명하지 못하는 모호한 헤드라인(예: `Build the future`), 과장되거나 추상적인 카피·이미지는 사용하지 않습니다. 카피는 기능·상태·행동을 직접 설명해야 합니다.
- AI 특유의 자유분방한 UI/UX와 기계적인 레이아웃을 만들지 않습니다. 제품의 작업 흐름과 시각적 위계를 먼저 정하고, 모든 요소에 같은 여백·같은 모서리 반경을 반복 적용하는 카드형 레이아웃을 피합니다.
- 다채로운 그라데이션, 특히 보라색→파란색 그라데이션을 배경·버튼에 장식으로 남용하지 않습니다. 목적·상태·브랜드 근거가 없는 장식은 제거합니다.
- 요술봉 아이콘 등 AI Slop의 대표적인 추상 아이콘, 목적이 없는 시각 효과, 의미 없는 Hover 애니메이션·마이크로 인터랙션은 넣지 않습니다. 모든 효과는 사용자 목표나 상태 변화와 연결되어야 합니다.
- 지나치게 매끄럽거나 작위적인 AI 생성 3D 일러스트는 사용하지 않습니다. 아이콘·이미지는 실제 대상·기능을 식별하게 하고, 플랫폼·제품의 기존 시각 언어를 우선합니다.
- 기본 산세리프, 특히 `Inter`를 생각 없이 적용하지 않습니다. 기존 제품·플랫폼의 타이포그래피와 정보 위계를 확인한 뒤 필요한 경우에만 선택합니다.
- 우주·로봇·관제센터·전술 화면·가짜 실시간 지표·AI 대시보드처럼 보이는 장치를 도메인 근거 없이 넣지 않습니다. 실제 제품이 그 대상을 다룰 때만 사용합니다.
- 디자인 결정을 유행 이름으로 정당화하지 않습니다. 프로젝트의 기존 디자인 시스템, 콘텐츠, 사용자 작업, 접근성 근거가 없으면 시각 장치를 추가하지 않습니다.
- 키보드 포커스가 항상 식별되고 주변과 구분되는지, 색상만으로 상태를 전달하지 않는지 확인합니다.
- 상호작용 애니메이션은 기능이나 정보 전달에 필요할 때만 사용하고, 불필요한 움직임은 사용자의 감속 설정을 존중합니다.
- 모델이 만든 시각 결과를 정답으로 간주하지 않습니다. 실제 렌더링, 제품 문맥, 접근성, 사용 흐름을 기준으로 판단합니다.

## 레이아웃 선택 기준

- UI·웹 작업에서는 화면을 억지로 채우는 `width: 100%`·`flex-grow: 1`을 남용하지 않습니다. 콘텐츠가 실제 크기를 결정해야 하는 영역에는 `fit-content`·`min-content`·intrinsic sizing을 검토합니다.
- 그리드·플렉스·일반 흐름 중 무엇을 쓸지는 콘텐츠 관계, 읽기 순서, 상호작용, 반응형 요구로 결정합니다. 12단 그리드·벤토·오프그리드·겹침을 기본값으로 삼지 않습니다.
- 모서리, 테두리, 그림자, 색상은 기존 디자인 시스템과 상태·접근성 요구에 맞춥니다. 특정 모서리 값, 강한 테두리, 그림자, 고대비를 미학적 규칙으로 강제하지 않습니다.
- 좌측 텍스트·우측 캡처, 카드, 고정 사이드바, Command Bar(`Cmd+K`)는 제품 작업에 실제로 필요할 때만 사용합니다. 화면을 다르게 보이게 하려는 이유만으로 대체하지 않습니다.
- 시각적 변형과 점진적 공개는 정보 위계, 작업 속도, 발견 가능성, 키보드 접근성을 개선할 때만 적용합니다. 기존 제품 디자인 시스템과 사용자의 명시적 지시가 있으면 그것이 우선입니다.

## 반응형 웹 구현 규율

- 지원 범위가 정해진 반응형 화면은 작은 뷰포트의 읽기 순서와 조작을 먼저 정하고, `min-width`로 넓은 화면을 확장합니다. 데스크톱을 줄인 뒤 깨진 부분을 임시 패치하지 않습니다.
- 브레이크포인트마다 글자와 여백을 딱 끊어 바꾸지 않습니다. `clamp()`·유체 여백·intrinsic sizing은 실제 콘텐츠를 보존할 때 사용합니다.
- `width: 100%`·`flex-grow: 1`로 모든 컨테이너를 늘리지 않습니다. 가로 오버플로우·잘린 텍스트·겹침은 줄바꿈·재배치·콘텐츠 축소·명시적 스크롤 중 목적에 맞는 방식으로 처리합니다.
- 카드와 컨테이너는 의미가 있을 때 사용합니다. 카드 수를 줄이거나 비대칭으로 바꾸는 것 자체를 품질 목표로 삼지 않습니다.
- 글꼴과 색상은 기존 제품 규칙을 먼저 확인합니다. 관습적인 `Inter`·`Roboto`·`Arial`, 회색+보라/파랑 네온 조합을 근거 없이 고르지 않으며, 가독성·대비·fallback을 검증합니다.
- 반응형 규칙은 시각적 변주가 아니라 정보 위계와 사용성 개선을 위해 추가합니다. 실행하지 않은 화면 크기·접근성 검증은 완료로 보고하지 않습니다.
