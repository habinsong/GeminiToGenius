# agy-focus 변경 기록

## 2.8.0 — 2026-08-03

- 공식 출처마다 근거 발견·구현 영향·검증 게이트가 같은 evidence matrix 행에 있는지 확인합니다.
- Chrome 렌더 검사가 실제 CSS/DOM 모션을 감지하고 `prefers-reduced-motion` emulation 경로를 실행합니다.
- Antigravity 공식 Hooks·Chrome·WCAG 2.2·Google HCI 자료를 계획 결정과 런타임 검증에 연결합니다.

## 2.7.0 — 2026-08-03

- `PreToolUse` 확인 응답을 Antigravity 공식 결정값인 `ask`로 맞춥니다.
- `Stop` 소스·조사 게이트의 재시도 횟수 우회를 제거해 미완료 인테이크나 공식 근거가 있으면 계속 상태를 유지합니다.
- `view_file`은 성공한 transcript 도구 호출만 전체 읽기 증거로 인정하며 실패·오류 호출은 제외합니다.
- `/GTG` 읽기·검토·진단 요청은 명시적 변경 지시가 없으면 계획서·문서·코드 쓰기도 차단합니다.

## 2.6.0 — 2026-08-03

- `/GTG` UI 조사 완료 조건을 공식 URL 4개 이상, 서로 다른 호스트 3개 이상, 플랫폼·접근성·성능·인간 중심 연구 중 3개 이상 분야로 강화하고 모델 보고서가 실제 읽은 URL을 모두 인용하는지 확인합니다.
- UI 계획에 adaptive `reflow`·`reveal`·`presentation`, 전체 화면에서 compact로 바뀌는 조건, WAI-ARIA 키보드 패턴, 근거 발견·구현 영향·검증 게이트·버린 대안 기록을 추가했습니다.
- 구현 계획에 intent/source of truth를, 검증 계획에 실제 flow trace·계획-구현 대조·브라우저 화면 관찰·독립 기준을 추가했습니다.
- 마지막 UI 검증에서 계획에 적은 변경 파일과 Route가 실제 구현에 존재하는지 대조합니다. 문서만 그럴듯하게 채우고 다른 파일을 건드리는 완료를 막습니다.
- Antigravity 공식 디렉터리 도구명 `list_dir`를 소스 선독 전 차단 테스트에 포함했습니다. 폴더 요약은 파일 전체 읽기로 세지 않습니다.
- Apple 2026 HIG, Android adaptive guidance, Chrome I/O 2026, WCAG/APG, Google GUIDE·HCI 연구를 한 스타일 강제가 아니라 결정·영향·검증 근거로 사용합니다.

## 2.5.0 — 2026-08-02

- website·webpage·landing page·static page를 단일 페이지 계획으로 통과시키지 않고 기본 2개 이상 Route 계약으로 고정했습니다. 진짜 단일 화면 앱만 예외로 남겼습니다.
- `/GTG` UI 계획은 Apple·Google·Chrome·W3C 등 서로 다른 공식 출처 2개 이상과 evidence matrix를 요구합니다.
- visual direction을 `restrained` 또는 `expressive`로 선택하고, 모션의 목적·트리거·duration/easing·예산·감속 경로를 계획과 검증에 기록하게 했습니다.
- Chrome View Transition·scroll-driven 효과와 적응형 레이아웃을 지원 범위·fallback·접근성·Long Animation Frames 측정과 묶었습니다. 실험적 Grid lanes·masonry는 기본값에서 제외했습니다.
- `find`, `ls`, `tree`, `fd`, `rg --files`, `git ls-files` 같은 shell workspace 목록 명령도 실제 소스 인테이크 전에는 차단합니다.
- 연구·계획·검증 책임을 기존 훅에서 분리해 `research.py`를 추가했고, 모든 훅 모듈 260줄 이하 원칙을 유지했습니다.

## 2.4.0 — 2026-08-02

- `cat`, `sed`, `rg`, `git show`, 일반적인 스크립트 읽기로 README·docs·Markdown을 먼저 훑는 우회를 차단합니다.
- IDE-native analyze·inspect·explore로 문서 경로를 먼저 분석하는 우회도 전역 훅에서 거부합니다.
- workspace·폴더·파일 트리 탐색을 실제 소스 인테이크 전에 실행하는 우회도 거부하며, 디렉터리 요약은 파일 전체 읽기로 세지 않습니다.
- 훅 payload로 들어오는 미등록 분석·탐색 도구는 소스 인테이크 전 기본 거부하고 `view_file`·등록 검증 명령만 허용합니다.
- 마지막 변경 뒤 실제 검증 명령의 성공 결과가 없으면 종료하지 않습니다. 출력만 만드는 명령은 검증으로 인정하지 않습니다.
- 소스 인테이크와 완료 검증을 별도 모듈에 두어 하네스 자체가 God Object로 커지지 않게 유지합니다.
- Antigravity 공식 `PreToolUse`·`Stop` 훅 계약과 WCAG 2.2 reflow, Apple 접근성, Chrome 응답성 측정 기준을 반영합니다.

## 2.3.0 — 2026-08-02

- UI 렌더 검사를 320px·768px·1280px 세 폭으로 확장해 모바일과 데스크톱 사이의 전환 실패를 찾습니다.
- UI 계획서가 시각 방향·선택 근거·대안·trade-off를 기록하게 하여 특정 스타일을 강제하지 않고 제품 맥락에 따른 자유도를 보존합니다.
- 검증 계획이 중간 폭과 실제 상태 전환을 포함하도록 강화하고, Gemini 3.6 Flash (High) 스킬에 호출·상태·데이터 경로까지 생략 없이 읽는 순서를 명시했습니다.
- Apple 2026 HIG, Material 3 Expressive, Chrome Long Animation Frames/View Transitions, W3C WCAG 2.2 근거를 계획·구현·검토 스킬에서 같은 기준으로 사용합니다.

## 2.2.0 — 2026-08-02

- Chrome 렌더 검사가 문서 언어·charset·title/h1/main·이미지 alt·접근 가능한 이름·24 CSS px 조작 영역·실제 focus 스타일을 확인합니다.

- 계획 검증이 최소 분량, motion 목적·duration/easing, 측정·접근성·target 항목을 요구합니다.
- 출력 전용 명령으로 가짜 URL·경로·검증 출력을 만드는 우회와 계획서의 명백한 placeholder 근거 URL을 차단합니다.
- Apple 2026 HIG, Android Material 3, Chrome View Transitions/Long Animation Frames, W3C WCAG 2.2, Google Research 근거를 동일한 UI 계획 자료로 정리했습니다.

- 저장소 근거와 UI 품질 검사를 훅 실행기에서 분리하고 모든 훅 모듈을 260줄 이하로 유지합니다.
