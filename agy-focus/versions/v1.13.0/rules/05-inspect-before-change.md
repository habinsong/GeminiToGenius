# 05 변경 전 확인

- 수정 전에 경로, 현재 내용, 사용자 변경 여부를 확인합니다.
- 가장 작은 변경 지점을 찾고 인접 코드는 요청과 무관하면 건드리지 않습니다.
- 기존 API·동작·파일 형식을 유지하며 새 추상화는 필요할 때만 추가합니다.
- 명령 실행 전 현재 목표에 직접 필요한지 확인합니다.

## UI·웹 작업의 출력 방향

- 실제 사용 목적·기능·상태·사용자 행동을 먼저 고정하고, 그 목적을 흐리는 AI Slop·AI SaaS 문법을 기본값으로 쓰지 않습니다.
- AI 특유의 서술형 텍스트, 실제 기능을 설명하지 못하는 모호한 헤드라인(예: `Build the future`), 과장되거나 추상적인 카피·이미지는 사용하지 않습니다. 카피는 기능·상태·행동을 직접 설명해야 합니다.
- AI 특유의 자유분방한 UI/UX와 기계적인 레이아웃을 만들지 않습니다. 제품의 작업 흐름과 시각적 위계를 먼저 정하고, 모든 요소에 같은 여백·같은 모서리 반경을 반복 적용하는 카드형 레이아웃을 피합니다.
- 다채로운 그라데이션, 특히 보라색→파란색 그라데이션을 배경·버튼에 장식으로 남용하지 않습니다. 목적·상태·브랜드 근거가 없는 장식은 제거합니다.
- 요술봉 아이콘 등 AI Slop의 대표적인 추상 아이콘, 목적이 없는 시각 효과, 의미 없는 Hover 애니메이션·마이크로 인터랙션은 넣지 않습니다. 모든 효과는 사용자 목표나 상태 변화와 연결되어야 합니다.
- 지나치게 매끄럽거나 작위적인 AI 생성 3D 일러스트는 사용하지 않습니다. 아이콘·이미지는 실제 대상·기능을 식별하게 하고, 플랫폼·제품의 기존 시각 언어를 우선합니다.
- 기본 산세리프, 특히 `Inter`를 생각 없이 적용하지 않습니다. 기존 제품·플랫폼의 타이포그래피와 정보 위계를 확인한 뒤 필요한 경우에만 선택합니다.

## 규격화된 UI 해체와 점진적 공개

- UI·웹 작업에서는 화면을 억지로 채우는 `width: 100%`·`flex-grow: 1`을 남용하지 않습니다. 콘텐츠가 실제 크기를 결정해야 하는 영역에는 `fit-content`·`min-content`·intrinsic sizing을 우선해 비대칭 여백을 만듭니다.
- 랜딩·에디토리얼·시각 중심 화면은 반응형과 접근성을 해치지 않는 범위에서 정형화된 12단 그리드와 규격화된 벤토를 기본값으로 삼지 않습니다. `grid-template-areas`, 서로 다른 비율·높이, 제한적인 `z-index` 겹침으로 off-grid 리듬과 레이어를 설계합니다.
- `border-radius: 12px~16px` 캡슐, 부드러운 박스 섀도우, 보라색·파란색 소프트 그라데이션을 기본 스타일로 배제합니다. 필요하면 0px 모서리, 강한 1px 단색 테두리, 고대비 타이포그래피, 의도가 드러나는 오프셋 그림자처럼 날카롭고 촉각적인 표현을 선택합니다.
- 좌측 텍스트·우측 앱 캡처의 관습적인 2단 배치를 자동 복제하지 않습니다. `clamp()` 기반 유체 타이포그래피와 큰 헤드라인의 크기 대비로 공간을 나누고, 텍스트가 수직·비선형 흐름을 만들 수 있게 구성합니다.
- 모든 데이터를 카드 안에 가두지 않습니다. 여백 자체를 구분선으로 쓰고, 고정 사이드바·정적 대시보드 틀은 줄이며, 필요할 때 나타나는 Command Bar(`Cmd+K`)와 맥락형 메뉴·팝업을 우선 검토합니다.
- 위 원칙은 시각 중심 웹 화면에 우선 적용합니다. 기능형 폼·설정·데이터 화면에서는 읽기 순서, 키보드 접근성, 반응형 안정성, 명령 발견 가능성을 해치지 않는 범위에서만 비대칭·겹침·점진적 공개를 사용합니다. 기존 제품 디자인 시스템과 사용자의 명시적 배치 지시가 있으면 그것이 우선입니다.

## 반응형 웹 구현 규율

- 가장 작은 지원 모바일 뷰포트에서 수직 흐름을 먼저 만들고, `min-width` 미디어 쿼리로 넓은 화면의 비대칭·겹침·다중 열을 점진적으로 확장합니다. 데스크톱 대칭 그리드를 먼저 만든 뒤 `max-width`로 찌그러뜨리는 방식은 사용하지 않습니다.
- 브레이크포인트마다 글자와 여백을 딱 끊어 바꾸지 않습니다. `clamp()` 기반 유체 타이포그래피와 유체 여백을 우선하고, `fit-content`·`min-content`·`max-content`로 콘텐츠 크기를 존중합니다.
- `width: 100%`·`flex-grow: 1`로 모든 컨테이너를 늘리지 않습니다. 가로 오버플로우·잘린 텍스트·깨지는 겹침은 숨겨서 해결하지 말고, 줄바꿈·수직 재배치·콘텐츠 축소·명시적 스크롤 중 의도에 맞는 방식으로 처리합니다.
- 카드 안에 카드를 계속 중첩하지 않습니다. 경계선·배경 면을 줄이고 거시적 여백과 서체 크기 대비로 영역을 구분하며, 3단 동일 카드 열 대신 `grid-template-areas`와 제한적인 `z-index`·오프셋으로 반응형 리듬을 만듭니다.
- `Inter`·`Roboto`·`Arial`을 무근거 기본 폰트로 사용하지 않습니다. 기존 제품 글꼴 체계가 없을 때는 목적이 분명한 디스플레이 서체와 본문 서체를 짝짓고, 가독성·로딩·대체 폰트를 함께 확인합니다.
- 회색 배경과 보라색·파란색 네온 그라데이션을 기본 팔레트로 만들지 않습니다. 색상은 의미 있는 이름의 OKLCH 토큰과 틴트로 정의하고, 대상 브라우저의 지원 범위에 맞는 명시적 fallback을 둡니다. 1px 단색 테두리와 목적 있는 오프셋 그림자를 우선합니다.
- 반응형 규칙은 시각적 변주가 아니라 정보 위계와 사용성 개선을 위해 추가합니다. 기존 제품 디자인 시스템·플랫폼 규칙·사용자의 명시적 지시가 있으면 그 범위 안에서 적용합니다.
