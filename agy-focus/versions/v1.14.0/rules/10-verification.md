# 10 검증

- 변경 작업은 상태 확인 → 한 가지 변경 → 가장 작은 직접 검증 순서로 진행합니다.
- 시작할 때 내부적으로 `목표·범위·완료 조건`을 고정하고, 종료 전 세 항목을 실제 증거와 대조합니다.
- 테스트·빌드·실행·UI 확인을 하지 않았다면 통과했다고 말하지 않습니다.
- 실패하면 같은 명령을 맹목적으로 반복하지 말고 원인 가설 하나를 세워 재검증합니다.
- 검증 결과가 없는 추정과 완료 판정을 섞지 않습니다.
- 내부 사고 과정을 장황하게 출력하지 말고 결론·근거·실행한 검증·남은 리스크만 보고합니다.

## UI·웹 결과 품질 게이트

- 헤드라인과 본문을 읽었을 때 실제 기능·대상·다음 행동이 드러나는지 확인합니다. 설명을 길게 늘여 쓰는 AI 특유의 서술형 텍스트, AI Slop·AI SaaS 카피, 모호한 미래 약속은 제거합니다.
- 화면의 시각적 위계가 기능 순서와 맞는지 확인합니다. 동일한 여백·동일한 둥근 모서리·반복 카드만으로 화면을 채우거나 기계적으로 정렬하지 않습니다.
- 배경·버튼의 다채로운 또는 보라색→파란색 그라데이션, 요술봉 같은 추상 아이콘, 작위적인 3D 이미지가 장식으로 들어갔는지 확인하고 근거가 없으면 제거합니다.
- Hover·전환·마이크로 인터랙션과 시각 효과마다 사용자 목표·상태 변화·피드백이라는 목적이 있는지 확인합니다. 목적이 없으면 넣지 않습니다.
- 폰트·카피·이미지가 제품 맥락과 실제 대상을 식별하게 하는지 확인합니다. `Inter` 기본값과 추상적 카피·이미지 사용을 결과물의 품질 기준으로 통과시키지 않습니다.
- 우주·로봇·관제센터·전술 화면·가짜 실시간 지표·범용 AI 대시보드처럼 보이는 요소가 제품 도메인과 무관하게 들어갔는지 확인하고 제거합니다.
- 화면이 실제 작업보다 AI 제품처럼 보이는지 확인합니다. 빛나는 배경, 가짜 상태 패널, 장식용 채팅창, 의미 없는 숫자, 범용 "AI" 배지를 추가하지 않습니다.
- 색상·모서리·테두리·그림자를 특정 스타일 유행에 맞추기 위해 강제하지 않았는지 확인합니다. 기존 디자인 시스템·콘텐츠·상태·접근성 근거가 없으면 제거합니다.
- 키보드 포커스가 보이고 인접 색상과 구분되는지, 상태·오류·진행 정보가 색상 하나에만 의존하지 않는지 확인합니다.
- 상호작용 애니메이션이 기능·정보 전달에 필요한지 확인하고, 불필요한 움직임은 감속 설정에서 비활성화되는지 확인합니다.

## 레이아웃 선택 검증 게이트

- 시각 중심 화면에서 `width: 100%`·`flex-grow: 1`이 콘텐츠 크기를 무시하고 화면을 채우는지 확인합니다. 필요한 영역에 `fit-content`·`min-content`·intrinsic sizing이 쓰였는지, 반대로 토큰을 기계적으로 끼워 넣지는 않았는지 함께 봅니다.
- 그리드·플렉스·일반 흐름 선택이 콘텐츠 관계와 읽기 순서를 설명하는지 확인합니다. 12단 그리드·벤토·오프그리드·겹침을 단순한 차별화 수단으로 쓰지 않습니다.
- 모서리·테두리·그림자·색상이 기존 디자인 시스템과 상태·접근성 요구에 맞는지 확인합니다. 특정 값이나 강한 대비를 미학적 기본값으로 강제하지 않습니다.
- 좌측 카피·우측 제품 캡처, 모든 데이터를 담은 카드, 고정 사이드바·정적 대시보드 프레임이 실제 작업에 필요한지 확인합니다. 큰 헤드라인·`clamp()`·여백·Command Bar·맥락형 메뉴도 같은 기준으로 검토합니다.
- 비대칭·겹침·유체 타이포그래피·점진적 공개는 기능·정보 위계·반응형 상태·접근성 근거가 있을 때만 통과시킵니다.

## 반응형 웹 결과 검증 게이트

- 가장 좁은 지원 모바일 상태에서 수직 흐름·읽기 순서·터치 가능한 크기를 먼저 확인하고, 넓은 상태는 `min-width` 확장으로 자연스럽게 이어지는지 확인합니다. 데스크톱을 줄여 놓은 흔적과 `max-width` 패치가 남아 있으면 통과시키지 않습니다.
- 브레이크포인트 사이에서 글자·여백이 부드럽게 흐르는지 확인합니다. `clamp()`·intrinsic sizing이 실제 콘텐츠를 보존하는지, `width: 100%`·`flex-grow: 1` 남용이 없는지 확인합니다.
- 좁은 폭에서 가로 스크롤·잘린 텍스트·겹침으로 가려진 조작·깨진 이미지가 없는지 확인합니다. 오버플로우를 `hidden`으로 숨겨 실패를 감추지 않았는지 확인합니다.
- 카드 중첩과 동일한 3단 카드 열이 정보 위계를 대신하고 있지 않은지 확인합니다. 컨테이너와 여백이 실제 의미를 만드는지 확인합니다.
- `Inter`·`Roboto`·`Arial`이 무근거 기본값인지, 디스플레이·본문 폰트 페어링과 fallback이 정의됐는지 확인합니다. 색상 토큰은 프로젝트 맥락·대비·상태를 설명해야 합니다.
- 어두운 화면, 전술적 화면, 우주·로봇·관제센터 모티프, 가짜 지표와 AI 대시보드가 기능 근거 없이 추가되지 않았는지 확인합니다. 기능형 화면의 접근성·발견 가능성과 충돌하면 시각 효과를 제거합니다.
