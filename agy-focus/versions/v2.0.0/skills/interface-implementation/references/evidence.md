# 공식 UI 근거

정확한 수치·검토 기준·출처가 필요할 때만 읽습니다.

- W3C WCAG 2.2: [본문 대비 4.5:1·큰 글자 3:1](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [보이는 키보드 포커스](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html), [최소 24×24 CSS px 타깃](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), [320 CSS px 리플로우](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html), [상호작용 애니메이션 비활성화](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)
- web.dev: [콘텐츠 기준 반응형 브레이크포인트](https://web.dev/articles/responsive-web-design-basics), [`prefers-reduced-motion`](https://web.dev/articles/prefers-reduced-motion), [INP 200ms 이하](https://web.dev/articles/optimize-inp), [CLS 0.1 이하와 크기 예약](https://web.dev/articles/optimize-cls)
- GOV.UK Service Manual: [짧고 직접적인 UI 문구, 중요한 단어 우선](https://www.gov.uk/service-manual/design/writing-for-user-interfaces)
- Nielsen Norman Group: [애니메이션은 목적이 있어야 하며 반복 움직임은 주의를 소모함](https://www.nngroup.com/articles/animation-usability/)
- Apple Human Interface Guidelines: [Hierarchy, harmony, consistency, accessibility](https://developer.apple.com/design/human-interface-guidelines/)

수치는 측정·검사했을 때만 완료 근거로 사용합니다. 제품 문맥과 기존 디자인 시스템이 우선이며, 특정 시각 스타일을 공식 기준처럼 강제하지 않습니다.
