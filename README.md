## 하는 일

- 작업을 등록할 때 완료 조건과 검증 명령을 먼저 고정합니다. 등록을 마친 뒤에는 통과하기 쉬운 임의의 명령으로 바꿀 수 없습니다.
- `verify`는 등록된 명령을 실제로 실행하며, 종료 코드와 소요 시간, 검사 대상 파일 목록을 투명하게 기록합니다. 검사 대상 파일이 바뀌면 이전 성공 기록은 효력을 잃습니다.
- `certify`는 완료 주장과 실행 근거를 단일 파일에 묶어 저장합니다. `replay`는 별도 상태 데이터베이스 없이 해당 파일과 현재 작업 공간만으로 결과를 다시 검증합니다.
- 검사에서 실행하지 못한 파일이나 판단할 수 없었던 범위도 결과에 있는 그대로 명시합니다. 비어 있는 목록을 두고 '모두 확인 완료'로 포장하지 않습니다.
- 세션이 끊겨도 등록된 작업과 검사 결과, 기록 메모는 그대로 보존됩니다. 새 세션에서는 `tasks` 명령으로 검색해 `attach`로 작업을 곧바로 이어갈 수 있습니다.
- 코드를 수정한 뒤에는 `structure` 검사가 빈 함수나 새 TODO, 대형 파일에 누적된 기능, 지나치게 불어나는 클래스를 차단합니다. 구현이 하나뿐인 추상화나 인자만 넘기는 래퍼, 호출하는 곳이 없는 새 정의도 검토 대상으로 함께 알립니다.
- 문서를 작성한 뒤에는 `prose` 검사가 한국어와 영어 상투구, 과장 표현, 번역투가 몰린 문단, 대구, 끊기는 문장을 줄 번호와 함께 찾아 0~100점 점수로 환산합니다. 논문·일상 글·문학처럼 글의 갈래를 고를 수 있으며, 파일로 저장하지 않은 글은 표준 입력으로 검사할 수 있습니다.
- 윤문한 글은 원문과 꼼꼼히 대조하여, 수치와 인용구, URL, 코드가 바뀌지 않았는지와 수정된 단어 비율을 계산해 드립니다.
- 검증 과정에서 확인한 저장소별 실수(예: 존재하지 않는 함수 이름 호출)를 근거 파일과 함께 교훈으로 남겨 두면, 다음 세션 첫 턴에 그 기록을 확인하실 수 있도록 안내합니다.

## 설치

macOS 또는 Linux 환경, Python 3.10 이상, Git이 필요합니다. 외부 Python 패키지는 요구하지 않습니다.

```bash
git clone https://github.com/habinsong/GeminiToGenius.git
cd GeminiToGenius
bash scripts/install.sh
```

설치 스크립트는 홈 디렉터리에서 지원 호스트를 스스로 탐색하여 설치하며, 설치를 진행하기 전에 별도 임시 디렉터리에서 패키지 무결성을 검증합니다. 감지된 호스트가 없으면 Antigravity 전역 플러그인으로 설치합니다. 설치를 마친 뒤에는 해당 호스트를 재시작해 주십시오.

| 호스트 | 설치 방식 |
| --- | --- |
| Antigravity 데스크톱·IDE | 자동 감지 또는 프로젝트별 설치를 지원합니다. |
| Antigravity CLI (`agy`) | 자동 감지 후 `agy plugin install`까지 함께 실행합니다. |
| Gemini CLI | `--platform gemini-cli`를 지정해 직접 설치합니다. |

특정 프로젝트에만 적용하시려면 다음과 같이 실행하시면 됩니다.

```bash
bash scripts/install.sh --workspace /absolute/path/to/project
```

설치 상태 확인과 제거에는 아래 명령을 사용합니다.

```bash
python3 scripts/install.py doctor
python3 scripts/install.py uninstall
```

## 쓰는 법

설치 후에는 평소처럼 자연어로 요청하시면 됩니다. 슬래시 명령이나 별도의 명세 파일을 번거롭게 작성하실 필요가 없습니다.

```
로그인하면 500이 납니다. 원인 찾아서 고쳐 주세요.
```

코드 동작이나 타입, 호출 관계를 바꾸는 작업은 파일 하나만 수정하더라도 빌드와 필수 시험을 완료 계약에 연결하도록 안내합니다. PRD가 있으면 요구사항별 검사를 연결하며, 단순 문답이나 문구 수정은 관련 검사만 확인하고 마무리합니다.

3.1.0은 결과물을 직접 읽는 구조·문체 검사와 교훈 기록을 더하고, 상시 규칙을 "기억보다 원문, 끝내기 전에 스스로 반박하기" 중심으로 다시 썼습니다. 3.2.0은 한국어 윤문을 갈래별 스킬 세 개로 나누고 문체 점수를 붙였으며, 3.3.0은 표준 입력과 윤문 전후 비교를 더하고 긴 문서에서 경고가 쏟아지던 문제를 고쳤습니다. 각 버전에서 무엇을 확인했고 무엇을 확인하지 못했는지는 [3.1.0](docs/verification/3.1.0.md), [3.2.0](docs/verification/3.2.0.md), [3.3.0](docs/verification/3.3.0.md) 검증 기록에서 확인하실 수 있습니다.

### 한국어 글을 쓰거나 다듬을 때

```
이 보고서 문단 AI 티 안 나게 고쳐 줘.
```

스킬 이름을 직접 부르실 필요는 없습니다. 스킬 설명에 `자연스럽게`, `번역투 빼 줘`, `답장 써 줘`, `소설처럼` 같은 일상 표현을 담아 두었으므로, 논문·보고서는 `gtg-korean-academic`, 카톡·메일·후기는 `gtg-korean-everyday`, 소설·수필·시는 `gtg-korean-literary`, 그 밖의 일반 글은 `gtg-writing`이 맡아 처리합니다. 호스트가 요청에 맞는 스킬을 실제로 여는지는 직접 확인하지 못했습니다.

윤문 스킬은 원문의 수치·인용·주장 강도를 바꾸지 않게 하고 끝내기 전에 `prose` 검사를 돌리도록 유도합니다. 에이전트는 턴 시작 안내에 담긴 실행기 경로로 이 검사를 부르며, 저장소에서 직접 실행해 보실 수도 있습니다.

```bash
python3 -m gtg prose --register academic paper.md
python3 -m gtg prose --register everyday --original draft.md reply.md
python3 -m gtg prose --register everyday - <<'EOF'
내일 3시에 봐요. 늦으면 연락 줘요.
EOF
```

| 옵션 | 하는 일 |
| --- | --- |
| `--register` | `general`(기본), `academic`(논문·보고서), `everyday`(대화·메시지·후기), `literary`(소설·수필·시) 가운데 고릅니다. 같은 표현이어도 논문에서는 학술 관례이고 대화에서는 어색할 수 있으므로 갈래마다 규칙을 끄고 완화하고 보강합니다. |
| `-` 또는 `--text` | 파일로 저장하지 않은 글(채팅 답변 등)을 표준 입력이나 명령줄로 받아 검사합니다. |
| `--original` | 윤문본을 원문과 대조합니다. 수치·인용·URL·코드가 바뀌었으면 종료 코드 1을 반환하고, 수정된 단어 비율도 함께 알려 드립니다. |
| `--min-score` | 점수가 이 값(0~100)보다 낮은 문서가 있으면 종료 코드 1을 반환합니다. |

점수는 찾은 신호를 글 분량(문장 10개 단위)으로 나눈 값이며 A(90점 이상), B(75점), C(60점), D 등급으로 구분합니다. AI가 썼을 확률이 아닙니다. 사람이 직접 쓴 에세이의 8%도 90점에 미치지 못했으므로, 점수가 낮다는 이유만으로 AI가 작성했다고 섣불리 단정해서는 안 됩니다.

## 대상 모델

3.1.0의 지침은 Gemini 4 Argon(2026-10-13 공개)과 Gemini 3.8 Flash(2026-09-02 공개)를 염두에 두고 작성했습니다. 두 모델은 벤치마크 점수에 비해 실제 저장소 작업에서 코드 동작을 꾸며내거나, 미완성 코드를 두고 완료했다고 주장하거나, 지키겠다고 밝힌 제약을 곧바로 어긴다는 사용자 보고가 있었습니다. 따라서 GTG는 모델의 자체 보고 대신 실제 검사 결과와 다시 열어 본 원문을 근거로 삼게 하며, Google의 Gemini 프롬프트 지침에 맞춰 금지 사항을 규칙 끝에 구체적으로 정리했습니다.

실행 코어는 모델 이름으로 분기하지 않으며 호스트가 지정한 모델과 사고 수준을 임의로 변경하지 않습니다. Google 공식 문서는 두 모델 모두 기본 사고 수준을 medium으로 권장합니다. Argon 문서는 여러 파일에 걸친 소프트웨어 작업에 high를 권장하며, 3.8 Flash 문서는 복잡한 코드와 에이전트 작업에 medium을, 까다로운 다단계 추론에는 high를 권장하므로 작업 성격에 맞춰 호스트 설정에서 선택하시면 됩니다. 2026-10-28에 발표된 Gemini 4 Carbon은 아직 일반 공개 전이므로 세부 사양을 단정하지 않았습니다. 이 지침이 실제 환경에서 환각과 과장을 얼마나 줄여 주는지는 아직 정량 측정하지 못했습니다.

## 확인한 것

| 항목 | 확인한 결과 |
| --- | --- |
| Antigravity 2.12.2 | 다단계 요청 환경에서 작업 등록과 검사 실행, `certify`, `replay` 동작을 확인했습니다. |
| Antigravity CLI 1.1.28 | 공식 패키지 검증을 통과했고 훅 2개가 정상 발행되었습니다. |
| 완료 증명서 | 검사 대상 파일의 한 줄을 바꾸면 재현 검증이 실패하고, 원복하면 다시 통과함을 확인했습니다. |
| 동일 모델 비교 | GTG 사용 여부와 무관하게 모두 14/14 통과했습니다. 이 결과가 제품 간 우열이나 단일 턴 작업 품질의 개선을 입증하는 것은 아닙니다. |
| 3.3.0 오프라인 시험 | 전체 513개 시험이 통과했습니다. 문체 검사를 의도적으로 훼손한 변형 56개를 시험이 모두 잡아내는지 확인했고(`scripts/mutation_check.py`), 스킬 문서에 수록된 수정 예시 21개를 검사기에 다시 대조했습니다. 실제 Gemini 호출은 진행하지 않았습니다. |
| 문체 점수 | 한국어 말뭉치(KatFish)에서 사람 글과 LLM 글을 가르는 확인용 AUC는 에세이 0.945, 초록 0.798, 시 0.669를 기록했습니다. 사람이 작성한 논문 본문 100편은 A 98편, B 2편으로 집계되었습니다. Gemini가 직접 작성한 글로는 실측하지 않았습니다. |

구체적인 수치와 실행 환경, 미확인 범위는 [검증 기록](docs/verification/README.md)에 가감 없이 정리해 두었습니다.

## 아직 확인하지 못한 것

- Windows 환경 설치 및 네트워크 파일 시스템 환경에서의 실행 잠금 동작
- 실제 전원 차단 후 복구 과정, 여러 날에 걸친 장기 작업, 다양한 모델에서의 반복 시험
- Go·Rust 환경 및 컴파일하여 실행하는 TypeScript 환경에서의 실행 범위 관측
- 토큰 사용량 및 실제 비용 측정
- 3.1.0 지침과 구조·문체 검사, 교훈 기록이 실제 Gemini 4 Argon·Gemini 3.8 Flash의 환각과 미완성 보고를 얼마나 줄여 주는지 여부
- Gemini가 직접 작성한 한국어의 문체 점수(현재 점수 기준은 사람 글과 2024년 LLM 글로만 보정했습니다. 고정 프롬프트 26개로 직접 측정하는 절차는 [evals/prose](evals/prose/README.md)에 마련되어 있습니다)
- 한국어 윤문 스킬이 실제 Gemini의 윤문 완성도를 얼마나 높이는지, 모호한 요청에 맞춰 적절한 스킬이 매끄럽게 열리는지 여부
- 일상 글·소설·수필·영어 환경에서 점수가 갖는 변별력(라벨이 붙은 데이터가 없어 단위 시험 문장과 문서 예시로만 확인했습니다)
- 데스크톱 Antigravity의 웹 도구 식별자(SDK 소스의 `search_web`, `read_url_content`와 완전히 일치하는지 여부)

## 개발

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests
python3 scripts/catalog.py --check
```

현재 작업 기록과 파일별 원문 목록은 저장소에 커밋하지 않는 `docs/development/` 폴더에서 관리합니다. 문체 검사를 다시 캘리브레이션하거나 변형 시험으로 검증의 빈틈을 점검하는 방법은 [3.3.0 검증 기록](docs/verification/3.3.0.md)과 `scripts/prose_calibration.py`, `scripts/mutation_check.py` 도움말에 상세히 안내되어 있습니다.
